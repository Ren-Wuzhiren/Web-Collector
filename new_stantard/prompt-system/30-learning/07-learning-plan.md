# 学习规划

> 场景：想系统学一个方向，但不知道先学什么、每周怎么安排。
> 适用：计算机网络、Redis、Docker、数据库原理、求职准备等。
> 不适用：只想解决一个具体问题；用概念卡或诊断卡。
> 关键原则：**先定目标，再看差距，只规划 8 周；计划必须可调整。**

## 可直接复制的提示词

```text

{{LEARNER_CARD}}

2. 对照目标做差距分析：已会什么、缺什么、哪些是伪需求。
3. 给出 8 周主线，每周一个主题 + 一个可交付成果。
4. 每周安排：输入（看书/文档）、练习、项目/实验、复盘的比例。
5. 给出 3 个检查点（第 2/4/8 周），说明如何判定是否达标。
6. 列出核心资源：优先官方文档/经典教材，最多 3 个，不要资源堆砌。
7. 给出“进度落后时怎么砍”的优先级。
8. 列出 3 个常见坑与应对。

# 5. 约束与非目标
- 只规划 8 周，后续滚动调整；不排到毕业。
- 每周投入必须匹配我的真实时间，不假设每天有空。

- 不堆砌课程/书单；每类最多 3 个资源。
- 不承诺“学完就能进大厂”；只承诺可验证的能力提升。
- 不把考研/就业/竞赛路线混在一起；先选一个主目标。

## 常见坑

# 7. 示例
目标：8 周内建立计算机网络的核心理解，能解释一次网页访问的完整链路。
第 1–2 周：分层模型 + 链路层/IP；交付：画出数据包封装过程。
第 3–4 周：TCP/UDP + 可靠传输；交付：解释三次握手、四次挥手、TIME_WAIT。
第 5 周：HTTP/HTTPS + DNS；交付：用 curl/wireshark 跟踪一次请求。
第 6 周：路由与 NAT；交付：解释家里上网到服务器的路径。
第 7 周：综合项目；交付：一次访问的端到端时序图 + 排错清单。
第 8 周：复习与自测；交付：闭卷讲清 10 个核心问题。

# 8. 验收标准与自检
- [ ] 目标与验收方式明确。
- [ ] 差距分析基于我的真实背景，不假设。
- [ ] 每周都有可交付成果，不只是“看书”。
- [ ] 时长与我可投入时间匹配。
- [ ] 有 3 个检查点与达标标准。
- [ ] 资源不超过 3 个/类。
- [ ] 有落后时的取舍规则。

# 9. 下一步

不要自动生成每天的学习内容。
```

## 规划原则

1. **一个主目标**：考研、就业、竞赛不要混排。
2. **以输出定输入**：每周先定交付物，再选资料。
3. **理论 + 实践**：计网配抓包，Redis 配项目，Docker 配部署。
4. **留缓冲**：每周最多排 80% 可用时间。
5. **滚动调整**：8 周后重新评估，不做一年期死计划。

## 以你当前情况为例

已学：C++、Java SE、SSM、Spring Boot、Git、Maven、Tomcat、数据结构与算法、操作系统、MySQL、Linux；做过 Spring Boot + Vue 博客；Redis、Docker 碎片化；正在学计网。

可选主线：

- **主线 A：计网打透**（当前学期）：8 周理解 + 抓包 + 排错。
- **主线 B：后端工程化**：Redis 缓存、Docker 部署、测试与可观测性，围绕博客做。
- **主线 C：求职准备**：数据结构/算法 + 项目深挖 + 计网/OS/数据库面试题。

一次只选一个主线，其余作为副线每周 1–2 小时。

## 常见失败与修法

| 失败 | 修法 |
|---|---|
| 计划太满 | 只排 80% 时间，留缓冲 |
| 只输入不输出 | 每周必须有交付物 |
| 资源堆砌 | 每类最多 3 个，优先官方文档 |
| 目标混杂 | 先选一个主目标 |
| 不做检查点 | 第 2/4/8 周验收 |
| 落后就放弃 | 预设“砍什么、保什么” |
