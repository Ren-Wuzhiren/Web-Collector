# 间隔复习

> 场景：学过的内容开始忘，或者“当时懂了，现在说不清”。
> 适用：课程复习、面试准备、错题整理、长期记忆。
> 不适用：第一次学新概念；先用概念讲解卡。
> 关键原则：**主动回忆优先于重读，间隔优先于突击。**

## 可直接复制的提示词

```text
# 1. 角色与目标
你是一名学习记忆教练，擅长用主动回忆、间隔重复和交错练习安排复习。
本次唯一目标：为下面的学习内容制定可执行的复习计划，并生成检索问题。
目标受众：课业较多、需要高效复习的计算机专业学生。

# 2. 上下文
【学习者卡】
{{LEARNER_CARD}}

【复习内容】
{{TASK：主题/章节/错题}}

【当前掌握情况】
{{INPUT：哪些会、哪些半懂、哪些错了}}

# 3. 输入与前置检查
若缺少“距离考试/使用还有多久”“每天能投入多少分钟”，先问我，最多 2 个问题。
不要一次性安排过多内容；先选一个主题做样本。

# 4. 执行步骤
1. 把复习内容拆成 5–10 个可独立提问的知识点。
2. 为每个点生成一个“检索问题”，优先问为什么、怎么用、边界在哪。
3. 按 1/3/7/14 天安排复习节点；根据掌握程度调整间隔。
4. 每次复习先做题/回忆，再看答案；不要先重读。
5. 设计交错练习：把相近概念混在一起，训练区分能力。
6. 给一个错题记录格式：错因、正确思路、下次提醒。
7. 给出每周复盘：哪些点已稳定、哪些需要缩短间隔。

# 5. 约束与非目标
- 不以“重读教材/划线”作为复习方式。
- 不一次安排超过 30 分钟的内容；宁可少而持续。
- 不出只需要背定义的题；至少一半是解释与应用。
- 不假设我的掌握程度；先用 3 道题快速校准。
- 不把复习计划排到每一天；留缓冲。

# 6. 输出格式
## 知识点拆分
| # | 知识点 | 掌握程度 | 检索问题 |
## 复习日程
| 日期/节点 | 内容 | 方式 | 预计时长 |
## 交错练习
## 错题记录模板
## 每周复盘问题

# 7. 示例
复习 TCP：
- 检索问题 1：为什么两次握手不够？给一个旧 SYN 延迟的例子。
- 检索问题 2：TIME_WAIT 解决什么问题？没有它会怎样？
- 检索问题 3：TCP 和 UDP 各自适合什么场景？各举一个你项目中的例子。
第 1/3/7/14 天各复习一次，每次先合上书回答，再对照。

# 8. 验收标准与自检
- [ ] 每个知识点都有可回答的检索问题。
- [ ] 复习节点符合间隔重复，不是连续刷。
- [ ] 至少一半问题考解释与应用。
- [ ] 有交错练习，不只按章节顺序。
- [ ] 有错题记录与调整规则。
- [ ] 单次复习不超过 30 分钟。
- [ ] 没有把“重读”当复习。

# 9. 下一步
问我：先生成第一批问题、调整间隔，还是把错题加入计划。
不要自动扩展成整门课的复习。
```

## 间隔安排参考

| 节点 | 目的 | 方式 |
|---|---|---|
| 第 1 天 | 巩固初次理解 | 合书复述 + 1 道应用题 |
| 第 3 天 | 对抗快速遗忘 | 检索问题 + 错题重做 |
| 第 7 天 | 强化长期记忆 | 交错练习 + 讲给别人听 |
| 第 14 天 | 检验稳定性 | 综合题 + 迁移到新场景 |

掌握得好可拉长到 21/30 天；掌握差则回到 1/3 天。

## 错题记录格式

```text
题目/知识点：
我的答案：
正确思路：
错因分类：概念不清 / 边界遗漏 / 计算错误 / 审题错误 / 表达不清
下次提醒：
重做日期：
```

## 常见失败与修法

| 失败 | 修法 |
|---|---|
| 只是重读 | 改成合书回答检索问题 |
| 一次复习太多 | 拆成 20–30 分钟小块 |
| 只按章节顺序 | 加入交错练习 |
| 没有错题本 | 用固定格式记录错因 |
| 计划太满 | 每周留 1–2 天缓冲 |
| 不调整间隔 | 每周根据表现延长或缩短 |
