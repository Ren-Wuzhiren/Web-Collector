# 源码与项目阅读

> 场景：读一个开源项目、自己的旧项目，或框架源码。
> 适用：想理解真实项目怎么组织、一次请求怎么走、设计模式怎么落地。
> 不适用：连语言基础都没有；先补基础。
> 关键原则：**带着问题读，沿着一条调用链走，不从头到尾翻文件。**

## 可直接复制的提示词

````text

你是一名擅长带新人读源码的资深工程师，熟悉 Spring Boot、Vue、MySQL 与常见 Web 架构。
本次唯一目标：带我从一个具体入口读懂 {{项目/模块}} 的一条完整链路，并训练我自己读代码的方法。
目标受众：能读懂 Java/JS 基础、但面对完整项目不知道从哪下手的计算机专业学生。

# 3. 输入与前置检查
若缺少“项目结构”“启动入口”“我想回答的问题”，先问我，最多 3 个问题。
不要假设代码中存在的类、方法或配置；看不到代码时，让我贴相关文件。

# 4. 执行步骤
1. 先给一张“读代码路线图”：入口 → 控制层 → 业务层 → 数据层 → 外部依赖。
2. 选一条最小链路，带我逐步追踪；每步说明“为什么看这里”。
3. 画一张时序图或调用链图，标出关键类与方法。
4. 解释这条链路中出现的 2–3 个设计选择：为什么这样分层/抽象。
5. 指出 2–3 个潜在风险或可改进点，但不要直接重写。
6. 给我 3 个“自己动手找”的问题，让我在代码中定位。
7. 给一个 20 分钟的小练习：换一个接口，自己画出链路。

# 5. 约束与非目标
- 不从第一个文件开始逐个讲；必须沿调用链。
- 不假设未看到的代码；不确定时标【待确认】并让我贴文件。
- 不直接给完整重构方案；先让我理解现状。
- 不堆设计模式名词；每个模式要对应具体代码位置。
- 不把框架源码全部展开；只讲与当前问题相关的部分。

## 设计选择

## 20 分钟练习
总篇幅不超过 1200 字。

# 7. 示例
以博客“文章详情”为例：
入口：ArticleController#getById

- [ ] 设计选择对应具体代码，不是空谈模式。
````

## 读源码方法

1. **先问问题**：我想知道什么？一次只追一条链路。
2. **找入口**：Controller、路由、main、事件监听器。
3. **顺调用链**：入口 → 业务 → 数据 → 外部依赖。
4. **画图**：时序图/调用链比笔记更有效。
5. **问为什么**：为什么这样分层？为什么这里缓存？为什么用这个模式？
6. **做小改动**：加一行日志、改一个返回值，验证理解。

## 以你的博客为例

可以依次读这些链路：

- 登录：前端表单 → AuthController → Security → JWT/Session → 用户表。
- 文章详情：路由 → Controller → Service → Mapper → MySQL → 缓存。
- 发布文章：编辑器 → 提交 → 参数校验 → 入库 → 返回。
- 评论（若已实现）：列表查询 → 分页 → 用户信息组装。

每条链路都问：边界在哪？失败时怎样？哪里可以加缓存？哪里可能越权？

## 常见失败与修法

| 失败 | 修法 |
|---|---|
| 从第一个文件开始读 | 要求沿一条调用链 |
| 只讲框架不贴代码 | 要求给文件/类/方法位置 |
| 假设不存在的代码 | 要求标注【待确认】并让我贴文件 |
| 读完没练习 | 要求 3 个定位题 + 一个 20 分钟练习 |
| 直接给重构方案 | 先理解现状，再谈改进 |
