# AI 辅助开发与计算机自学提示词系统

一套纯 Markdown、跨模型、可复用的提示词系统。它不追求“神奇咒语”，而是把**稳定内核 + 场景模块 + 上下文档案 + 验收机制**组合起来，让 AI 在开发与自学两条轨道上稳定产出可用结果。

## 这套系统解决什么问题

- 角色提示词很多，但每次都要重写，质量忽高忽低。
- 模型一上来就给代码/答案，不澄清需求，也不说明假设。
- 输出很长，却缺少验收标准，无法判断“做完没有”。
- 学习时直接抄答案，感觉懂了，实际不会。
- 换一个模型，原来的提示词就失效。

## 两条使用路径

### 快路径：5 分钟上手

1. 打开 `20-dev/` 或 `30-learning/`，选一个最接近的场景。
2. 复制卡片里的提示词（只复制提示词正文，不要复制最外层代码围栏）。
3. 替换 `{{PROJECT_CARD}}`、`{{LEARNER_CARD}}`、`{{TASK}}` 等变量；没有档案就先贴一段简短背景。
4. 发送。模型若追问，按卡片里的“前置检查”回答。
5. 用卡片末尾的验收清单检查输出。

### 完整路径：复杂任务

1. 打开 [`10-generator/generator.md`](10-generator/generator.md)。
2. 让生成器访谈你，产出任务规格卡。
3. 生成器会组装一份定制提示词。
4. 把定制提示词发给模型执行。
5. 用 [`00-core/03-rubric.md`](00-core/03-rubric.md) 复盘这次提示词哪里需要改。

## 核心原则

1. **一提示一任务**：一张卡只解决一个阶段的问题。
2. **上下文与指令分离**：项目细节放项目卡，场景卡只放方法。
3. **输出契约**：每张卡都规定格式、验收标准和停止条件。
4. **先检查再执行**：缺关键信息时最多追问 3 个问题，不猜。
5. **事实与推断分开**：不编造 API、命令、测试结果和引用。
6. **学习轨先尝试后答案**：AI 是教练，不是答案播放器。
7. **最小可行改动**：开发轨默认不顺手重构、不扩大范围。
8. **可评测、可迭代**：每次失败都回流到评分表和失败案例。

## 变量约定

| 变量 | 含义 | 来源 |
|---|---|---|
| `{{PROJECT_CARD}}` | 项目上下文 | `40-profiles/project-card.template.md` |
| `{{LEARNER_CARD}}` | 学习者背景与目标 | `40-profiles/learner-card.template.md` |
| `{{TASK}}` | 本次具体任务 | 用户输入 |
| `{{INPUT}}` | 代码、报错、文档、题目等原始材料 | 用户输入 |
| `{{CONSTRAINTS}}` | 技术栈、时间、兼容性、安全等限制 | 用户输入或项目卡 |
| `{{OUTPUT_FORMAT}}` | 期望输出形式 | 场景卡默认值，可覆盖 |
| `{{ACCEPTANCE}}` | 本次验收标准 | 场景卡默认值 + 用户补充 |
| `{{DEADLINE}}` | 时间预算 | 用户输入，可省略 |

## 跨模型使用建议

- 全部使用纯文本与 Markdown，不依赖某个厂商的 XML 标签、工具调用或文件上传。
- 关键约束在提示词开头和结尾各出现一次；长对话每进入新阶段，先重贴一次项目卡。
- 推理型模型不需要“逐步思考”的强制指令；要求它给结论、关键依据和不确定性即可。
- 上下文窗口较小的模型，优先只贴项目卡中与当前任务相关的片段。
- 同一张卡在不同模型上效果不同，用 `60-evals/` 的方法做 A/B，不要凭感觉换卡。

## 安全边界

- 不要把密钥、Token、真实用户数据、公司内部代码粘进对话。
- 粘贴代码前先脱敏；不确定是否敏感时，用最小复现片段代替整份文件。
- 要求模型执行删除、重置、迁移等破坏性操作时，先让它列出影响范围并等待确认。
- 模型给出的命令先在本地确认作用对象，再执行。

## 维护方法

新增一张场景卡的最小步骤：

1. 复制任意 `20-dev/` 或 `30-learning/` 卡片。
2. 保留九段式标题，替换角色、步骤、输出格式和验收标准。
3. 控制正文在约 1200 个中文字以内；细节放进项目卡。
4. 用 `60-evals/test-cases.md` 中相近的任务跑一次。
5. 在 `CHANGELOG.md` 记录改了什么、为什么改。
