# 标准测试任务

> 用途：验证这套提示词是否真的比裸提示词更好。
> 原则：同一模型、同一任务、各自新开对话；不反复挑选“好看的结果”。
> 记录到 [`results-v1.md`](results-v1.md)。

## 测试协议

1. 选一个模型，记录名称与版本。
2. 每个任务新开一个对话，避免上下文污染。
3. 先跑 A（裸提示词），再跑 B（系统提示词）。
4. 不做额外解释、不追加“再详细点”等提示。
5. 原样保存输出，按评分表打分。
6. 至少隔一天再复测一次，看稳定性。

**注意**：一次结果不足以证明优劣；如果 B 明显更差，优先修提示词，而不是换模型。

## 任务 1：模糊需求

**目标**：看模型是否先澄清，而不是直接写代码。

A（裸提示词）：

```text
帮我给博客加一个评论功能，用 Spring Boot 和 Vue。
```

B（系统提示词）：

使用 [`20-dev/01-requirements.md`](../20-dev/01-requirements.md)，项目卡用 [`40-profiles/blog-project.md`](../40-profiles/blog-project.md)，任务填“给博客加评论功能”。

**观察点**

- [ ] 是否先问使用者、登录方式、审核规则、非目标。
- [ ] 是否给出 Given/When/Then 验收标准。
- [ ] 是否明确不写代码。
- [ ] 是否列非目标与风险。

## 任务 2：偶发 Bug

**目标**：看模型是否先复现与假设，而不是盲改。

A（裸提示词）：

```text
我的 Spring Boot 接口有时候返回 500，帮我看看怎么修。
```

B（系统提示词）：

使用 [`20-dev/04-debugging.md`](../20-dev/04-debugging.md)，补一段模拟证据：

```text
现象：文章详情接口约 1% 请求返回 500，刷新后恢复。
日志：NullPointerException at ArticleService.java:88，article.getCategory().getName()。
环境：Java 17、Spring Boot 3.2、MySQL 8。
最近改动：给文章增加了“未分类”状态。
```

**观察点**

- [ ] 是否指出证据不足（缺完整堆栈/复现步骤）。
- [ ] 是否列 2–4 个假设并给验证方法。
- [ ] 是否避免“全部改一遍”。
- [ ] 是否给回归测试与根因解释。

## 任务 3：代码审查

**目标**：看模型能否发现并发/事务问题，而不是只挑风格。

A（裸提示词）：

```text
帮我 review 这段 Java 代码：
public void comment(Long articleId, Long userId, String content) {
    if (commentMapper.exists(articleId, userId)) {
        throw new BizException("请勿重复评论");
    }
    commentMapper.insert(articleId, userId, content);
}
```

B（系统提示词）：

使用 [`20-dev/05-code-review.md`](../20-dev/05-code-review.md)，项目卡用博客项目卡，审查范围填“评论提交方法，关注并发与重复提交”。

**观察点**

- [ ] 是否发现“先查后插”的并发竞态。
- [ ] 是否建议唯一索引 + 捕获 DuplicateKeyException。
- [ ] 是否给测试建议。
- [ ] 是否避免只提命名/格式。

## 任务 4：概念讲解 + 苏格拉底

**目标**：看模型是否一次一个概念、先问后答。

A（裸提示词）：

```text
解释一下 TCP 三次握手。
```

B（系统提示词）：

先使用 [`30-learning/02-concept-tutor.md`](../30-learning/02-concept-tutor.md) 讲“为什么两次握手不够”，再用 [`30-learning/03-socratic-practice.md`](../30-learning/03-socratic-practice.md) 追问。

学习者卡用 [`40-profiles/learner-card.me.md`](../40-profiles/learner-card.me.md)。

**观察点**

- [ ] 是否有直觉、定义、例子、反例。
- [ ] 是否标注类比边界。
- [ ] 是否一次只问一个问题。
- [ ] 是否在我未作答前不给最终答案。

## 任务 5：学习计划

**目标**：看计划是否匹配真实时间、有交付物、可调整。

A（裸提示词）：

```text
给我一个 8 周学完计算机网络的计划。
```

B（系统提示词）：

使用 [`30-learning/07-learning-plan.md`](../30-learning/07-learning-plan.md)，学习者卡用 [`40-profiles/learner-card.me.md`](../40-profiles/learner-card.me.md)，任务填“8 周建立计算机网络核心理解，能解释一次网页访问的完整链路”，时间填“每周 5 小时”。

**观察点**

- [ ] 是否确认目标用途与验收方式。
- [ ] 每周是否有可交付成果。
- [ ] 是否匹配 5 小时/周，不排满。
- [ ] 是否有检查点与落后取舍。

## 判定

- B 平均 ≥16/20：可用。
- B 至少 3/5 任务高于 A：结构有效。
- B 出现编造且未标注：先修全局契约与场景卡，不要继续扩展。
- B 明显更长但信息密度低：压缩场景卡，移除重复段落。
