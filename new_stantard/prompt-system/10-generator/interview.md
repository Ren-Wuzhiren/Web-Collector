# 访谈清单

> 用途：配合生成器使用。按任务类型选择分支，不要把所有问题都问一遍。
> 原则：能推断的先给默认值；只问会改变方案的问题；总数不超过 5 个。

## 开发任务分支

### 必问（4 个）

| # | 问题 | 为什么问 | 默认值（用户不答时） |
|---|---|---|---|
| 1 | 要解决谁的什么问题？现在怎么做？ | 决定目标与痛点 | 按“个人项目、单人使用”处理 |
| 2 | 技术栈、版本、现有代码/相关文件？ | 决定方案可行性 | 只给通用方案，标注需适配 |
| 3 | 本次交付物是什么？明确不做什么？ | 控制范围 | 只做最小可用版本 |
| 4 | 怎样算成功？必须通过哪些测试？ | 决定验收 | 能运行 + 关键路径手动验证 |

### 选问（最多 1 个，按风险挑）

- 有无兼容性要求（旧接口、旧数据、旧客户端）？
- 有无性能/并发/安全要求？
- 部署环境与限制（云、内网、容器、离线）？
- 时间预算与上线窗口？
- 团队规范（命名、分层、提交信息、审查流程）？
- 是否允许新增依赖或修改数据库结构？

### 开发任务不该问的

- 用户自己能通过读代码发现的结构。
- 与本次目标无关的“最佳实践偏好”。
- 已经有默认答案的风格问题（缩进、注释语言）。

## 学习任务分支

### 必问（4 个）

| # | 问题 | 为什么问 | 默认值 |
|---|---|---|---|
| 1 | 想学会什么？为了考试、项目、面试还是理解原理？ | 决定深度与练法 | 以“理解 + 能用”为目标 |
| 2 | 当前水平：学过什么、做过什么、哪里卡住？ | 决定起点 | 按“有编程基础、该主题初学”处理 |
| 3 | 本次/每周能投入多少时间？ | 决定计划粒度 | 按每周 5 小时、单次 45 分钟 |
| 4 | 怎样算学会？复述、做题、写代码还是做项目？ | 决定验收 | 能用自己的话解释 + 完成 2 道题 |

### 选问（最多 1 个）

- 偏好讲解、例子、练习、项目还是苏格拉底提问？
- 有没有指定教材/课程/考试大纲？
- 是否需要安排复习计划？
- 有没有必须产出的作品或笔记？

### 学习任务不该问的

- “你想不想学好”——没有信息量。
- 超过当前水平太多的分支细节；先诊断再决定。
- 让用户自己设计课程；那是教练的工作。

## 追问顺序决策树

```text
用户给的信息
   │
   ├─ 有没有说“做什么”？
   │    ├─ 没有 → 先问目标（问题 1）
   │    └─ 有 → 下一步
   │
   ├─ 有没有说“现在是什么样”？
   │    ├─ 没有 → 问现状/技术栈/水平（问题 2）
   │    └─ 有 → 下一步
   │
   ├─ 有没有说“交付什么/不做什么”？
   │    ├─ 没有 → 问边界（问题 3）
   │    └─ 有 → 下一步
   │
   ├─ 有没有说“怎样算成功”？
   │    ├─ 没有 → 问验收（问题 4）
   │    └─ 有 → 下一步
   │
   └─ 还有高风险未知项？→ 选问 1 个
        否则 → 停止提问，给默认假设，开始组装
```

## 提问措辞模板

不要这样问：

```text
请详细描述你的需求、技术栈、目标、约束、验收标准、时间安排……
```

这样问：

```text
为了不写偏，我需要确认 3 件事：
1. 这个功能给谁用？现在他们怎么完成这件事？
2. 后端是 Spring Boot 几？现有登录用 Session 还是 JWT？
3. 本次只要“能发评论”，还是也要审核和删除？前者我按最小版本做。
```

## 用户拒答时

```text
收到，我不再追问。先按以下假设推进：
1. {{假设 1}}
2. {{假设 2}}
3. {{假设 3}}
如果其中任何一条不成立，告诉我编号，我再调整。
```

## 访谈质量自检

- [ ] 问题总数 ≤5。
- [ ] 每个问题都会改变方案，而不是满足好奇。
- [ ] 已给默认值，用户可以不答。
- [ ] 没有把可以自行读取的代码信息拿来问。
- [ ] 问完后能填满任务规格卡的必填字段。
