# 剧本：每周复盘

> 适用：每周固定回顾开发/学习进展，调整下周计划。
> 不适用：日复盘；日复盘只需 3 分钟，不必用本剧本。
> 原则：**用证据说话，不凭感觉；只定下周 3 件事。**

## 复盘前准备（5 分钟）

- 本周提交记录 / 学习笔记 / 错题本。
- 本周计划与实际完成对比。
- 卡住的问题清单。
- 下周可用时间。

## 启动提示词

```text
帮我做本周复盘。请基于我提供的证据，不要安慰式评价，也不要替我制定宏大计划。

【学习者卡】
{{LEARNER_CARD}}

【本周计划】
{{计划}}

【实际完成】
{{完成项、未完成项、证据}}

【卡点】
{{哪里卡住、试过什么}}

【下周可用时间】
{{小时数/时间段}}

按以下结构输出：
1. 本周事实（只写有证据的）
2. 完成度与偏差原因
3. 学到的/暴露的问题
4. 下周 3 个优先事项（每项有验收标准）
5. 需要砍掉或延后的事
6. 一个需要调整的系统性问题（如计划太满、只输入不输出）
```

## 复盘结构

### 1. 本周事实

只写可验证的：

- 完成了什么（提交、文章、题目、项目里程碑）。
- 没完成什么。
- 投入时间（估算即可）。
- 卡点与尝试。

### 2. 偏差原因

区分：

| 类型 | 例子 | 对策 |
|---|---|---|
| 计划太满 | 排了 20 小时，实际 8 小时 | 下周只排 80% |
| 任务太大 | “学完计网” | 拆成一个章节/一个能力点 |
| 卡点未求助 | 一个 bug 卡 3 天 | 设 2 小时求助阈值 |
| 只输入不输出 | 看了视频没练习 | 每周必须有交付物 |
| 目标漂移 | 同时学 Redis、Docker、计网 | 只保留一个主线 |

### 3. 下周 3 件事

每件必须：

- 可在下周时间内完成。
- 有明确验收标准。
- 有第一步（10 分钟内能开始）。

示例：

```text
1. 完成计网第 3 章 + 画出 TCP 状态转换图。
   验收：能闭卷讲清 5 个状态及转换。
   第一步：先做 5 道诊断题。
2. 给博客加文章阅读数缓存。
   验收：命中缓存、更新一致、Redis 挂掉能降级。
   第一步：先测当前接口耗时基线。
3. 复习上周错题 10 道。
   验收：能独立做对 8 道。
   第一步：先分类错因。
```

### 4. 砍掉或延后

明确写“这周不做什么”，防止下周继续过载。

## 10 分钟精简版

时间紧时只回答三个问题：

1. 本周唯一真正完成的事是什么？
2. 最大的卡点是什么？
3. 下周只做哪一件事？

## 月度回看

每 4 周问一次：

- 主线还在吗？是否需要换？
- 哪些“学了”其实没学会？
- 项目是否还在推进，还是只剩看教程？
- 时间投入是否可持续？
- 下一个检查点是什么？

## 常见失败

| 失败 | 后果 | 修法 |
|---|---|---|
| 只写“这周很忙” | 无法改进 | 只写事实与证据 |
| 下周列 10 件事 | 继续完不成 | 只留 3 件 |
| 没有验收 | 无法判断完成 | 每件写验收标准 |
| 反复换主线 | 什么都不深 | 4 周内不换主线 |
| 只反省不调整 | 同样问题重复 | 每次只改一个系统性问题 |
