# 剧本：开发一个新功能

> 适用：有一个明确的新功能，从想法到可交付。
> 不适用：修 bug（用 `bug-fix.md`）、纯学习（用 `learn-topic.md`）。
> 原则：**每阶段有产物、有确认点；不跳阶段。**

## 阶段流程

| 阶段 | 使用场景卡 | 产物 | 进入下一阶段的条件 |
|---|---|---|---|
| 1 需求 | `20-dev/01-requirements.md` | 用户故事、验收标准、非目标 | 目标和边界确认 |
| 2 方案 | `20-dev/02-architecture.md` | 方案对比、数据模型、接口草案 | 选型确认，风险可接受 |
| 3 实现 | `20-dev/03-implementation.md` | 最小 diff、测试 | 本地验证通过 |
| 4 审查 | `20-dev/05-code-review.md` | 分级问题清单 | 无 Blocker，Major 已处理 |
| 5 测试 | `20-dev/06-testing.md` | 测试用例与结果 | 验收标准全部通过 |
| 6 交付 | `20-dev/08-delivery.md` | README/部署/回滚 | 检查清单通过 |

小功能可以合并 1–2 阶段，但**验收标准**不能省。

## 启动提示词

```text
我要开发一个新功能，请严格按阶段推进，不要跳步。

【项目卡】
{{PROJECT_CARD}}

【功能】
{{TASK}}

【已知约束】
{{CONSTRAINTS}}

现在只做第 1 阶段：需求澄清。
输出用户故事、Given/When/Then 验收标准、非目标、风险与待确认问题。
不要写代码，不要设计数据库。
完成后停下来，等我确认再进入架构阶段。
```

## 第 1 阶段：需求

检查：

- [ ] 目标能一句话说清。
- [ ] 每条故事有可判定验收标准。
- [ ] 至少 3 条非目标。
- [ ] 待确认问题不超过 5 个。

不通过就停在这里。**需求没对齐时写代码，是最贵的返工。**

## 第 2 阶段：方案

检查：

- [ ] 至少两个方案，且都有缺点。
- [ ] 推荐方案与现有技术栈兼容。
- [ ] 数据模型支撑验收标准。
- [ ] 接口含错误码与权限。
- [ ] 有迁移/回滚方案（如涉及数据）。

## 第 3 阶段：实现

要求模型：

```text
按已确认方案实现。先复述代码理解，再列改动文件与目的；
只做最小 diff，不重构无关代码；给出验证命令。
```

检查：

- [ ] diff 与计划一致。
- [ ] 没改无关文件。
- [ ] 有测试或手动验证步骤。
- [ ] 未验证项已标注。

## 第 4 阶段：审查

把 diff 贴给审查卡，要求按 Blocker/Major 优先。

检查：

- [ ] 无 Blocker。
- [ ] Major 已修复或有明确延期理由。
- [ ] 新增测试覆盖关键分支。

## 第 5 阶段：测试

检查：

- [ ] 正常、边界、异常、权限路径覆盖。
- [ ] 回归用例在修复/改动前能失败。
- [ ] 测试可重复运行。

## 第 6 阶段：交付

检查：

- [ ] README/环境变量更新。
- [ ] 数据库变更可回滚。
- [ ] 健康检查与日志可定位问题。
- [ ] 变更记录已写。

## 阶段推进话术

```text
第 {{N}} 阶段完成。产物：{{产物}}。
自检结果：{{通过项/未通过项}}。
请确认是否进入第 {{N+1}} 阶段；若未通过，先只修 {{问题}}。
```

## 常见失败

| 失败 | 后果 | 修法 |
|---|---|---|
| 需求没确认就写代码 | 大范围返工 | 第 1 阶段强制停下 |
| 方案只给一个 | 看不到取舍 | 要求至少两个方案 |
| 实现顺手重构 | 引入无关风险 | 明确非目标，审查 diff |
| 审查只看风格 | 漏掉并发/安全问题 | 按严重级别审查 |
| 测试只测 happy path | 上线后边界出错 | 强制边界/异常/权限用例 |
| 交付没回滚 | 出事无法恢复 | 第 6 阶段检查 |
