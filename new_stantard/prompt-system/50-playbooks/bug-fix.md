# 剧本：修一个 Bug

> 适用：有明确异常现象，需要定位根因并修复。
> 不适用：需求没定义清楚；先回需求澄清。
> 原则：**先复现、再假设、后修复；不盲改。**

## 阶段流程

| 阶段 | 使用场景卡 | 产物 | 通过条件 |
|---|---|---|---|
| 1 收集证据 | `20-dev/04-debugging.md` | 现象、复现步骤、日志、环境 | 能稳定复现或明确说明不能 |
| 2 定位根因 | `20-dev/04-debugging.md` | 假设表、验证结果、根因 | 根因能解释关键证据 |
| 3 最小修复 | `20-dev/03-implementation.md` | 修复 diff | 只改必要文件 |
| 4 回归测试 | `20-dev/06-testing.md` | 复现测试 + 回归结果 | 修复前失败、修复后通过 |
| 5 审查 | `20-dev/05-code-review.md` | 审查结论 | 无 Blocker |
| 6 复盘 | 本文件 | 根因、预防措施 | 有可执行改进项 |

## 启动提示词

```text
我遇到一个 bug，请按“复现 → 假设 → 验证 → 修复 → 回归”推进，不要一上来改代码。

【项目卡】
{{PROJECT_CARD}}

【现象】
{{什么操作、什么结果、期望什么}}

【证据】
{{完整报错/堆栈/日志/相关代码/环境版本}}

【已尝试】
{{做过什么、排除了什么}}

先做两件事：
1. 复述现象，判断证据是否足够；
2. 列出 2–4 个假设，按可能性与验证成本排序，并给每个假设设计一个最小验证实验。
在我确认根因前，不要给修复代码。
```

## 证据清单

- [ ] 触发步骤（从登录/启动开始）。
- [ ] 实际结果与期望结果。
- [ ] 完整异常堆栈，不只最后一行。
- [ ] 发生时间、频率、影响范围。
- [ ] 环境版本：JDK、框架、数据库、浏览器。
- [ ] 最近改动：代码、配置、数据、依赖。
- [ ] 已排除的假设与证据。

缺证据时，先加日志/复现，不要继续猜。

## 定位检查

- [ ] 每个假设都有验证方法，而不是“可能”。
- [ ] 一次只改一个变量。
- [ ] 根因能解释全部关键证据，不是只解释一部分。
- [ ] 明确说明“为什么之前没发现、为什么现在触发”。

## 修复检查

- [ ] 修复是最小改动。
- [ ] 没有顺手重构。
- [ ] 有能复现 bug 的回归测试。
- [ ] 修复前测试失败，修复后通过。
- [ ] 数据修复（如有）可回滚。

## 复盘模板

```text
## 根因
一句话：
## 触发条件
## 为什么没被现有测试发现
## 修复
## 预防
- [ ] 补测试
- [ ] 加校验/断言
- [ ] 加监控/告警
- [ ] 更新文档/规范
## 还有哪些类似位置可能受影响
```

## 常见失败

| 失败 | 后果 | 修法 |
|---|---|---|
| 没有复现就猜 | 修错地方 | 先复现或补观测 |
| 一次改多处 | 无法判断哪处生效 | 一次一个变量 |
| 只修表象 | 同类问题复发 | 追问根因与同类位置 |
| 不补回归测试 | 下次重构又坏 | 必须有一条复现测试 |
| 修完不复盘 | 同样错误重复犯 | 填复盘模板 |
