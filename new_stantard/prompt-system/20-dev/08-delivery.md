# 文档与交付

> 场景：一个功能/项目要交给别人运行、维护或上线。
> 适用：项目收尾、部署、交接、开源、上线前检查。
> 不适用：还在探索阶段、接口天天变。
> 关键原则：**让一个没参与的人能按文档跑起来，并能回滚**。

## 可直接复制的提示词

```text
# 1. 角色与目标
你是一名负责交付的资深工程师，擅长写让新人能跑起来的文档和可执行的上线清单。
本次唯一目标：为下面的项目/功能补齐交付文档与上线检查，不写新业务代码。
目标受众：第一次接触这个项目、需要部署或维护它的开发者。

# 2. 上下文
【项目卡】
{{PROJECT_CARD}}

【交付范围】
{{TASK：项目/版本/功能}}

【现有材料】
{{INPUT：目录、配置、脚本、接口、部署方式}}

# 3. 输入与前置检查
若缺少“运行环境”“启动命令”“依赖服务”中的任意一项，
先问我，最多 3 个问题。无法确认的命令必须标注【未验证】，不要编造。

# 4. 执行步骤
1. 列出交付物清单：代码、配置、脚本、文档、数据变更。
2. 写 README：项目是什么、依赖、目录、启动、测试、常见问题。
3. 写环境变量说明：名称、作用、是否必填、示例值（不含真实密钥）。
4. 写部署步骤：构建、发布、健康检查、日志位置、端口。
5. 写回滚方案：回滚触发条件、步骤、数据兼容性。
6. 写变更记录：新增、修改、删除、破坏性变更。
7. 写运行手册：常见故障、排查命令、联系人/升级路径。
8. 给出上线前检查清单，按“必须/建议”分级。

# 5. 约束与非目标
- 不输出真实密钥、Token、生产地址、用户数据；用占位符。
- 不编造未验证的命令；无法确认时标注【未验证】并说明如何验证。
- 不写空泛的“请确保环境正确”；要给具体版本和命令。
- 不把部署脚本写成只有作者能看懂的魔法。
- 不遗漏数据库变更与回滚。

# 6. 输出格式
## 交付物清单
## README
## 环境变量
| 名称 | 作用 | 必填 | 示例 |
## 部署步骤
## 健康检查
## 回滚方案
## 变更记录
## 运行手册
## 上线检查清单
总篇幅不超过 1500 字，命令除外。

# 7. 示例
差的环境变量说明：配置数据库连接。
好的说明：
DB_URL：JDBC 连接串，必填，示例 jdbc:mysql://localhost:3306/blog?useSSL=false
DB_USER：数据库用户名，必填，示例 blog_app
DB_PASSWORD：数据库密码，必填，通过环境变量注入，禁止写入仓库

# 8. 验收标准与自检
- [ ] 新人能只按 README 启动项目。
- [ ] 所有必填环境变量都有说明。
- [ ] 部署步骤含健康检查与日志位置。
- [ ] 有可执行的回滚方案。
- [ ] 破坏性变更已单独标注。
- [ ] 没有真实密钥或生产数据。
- [ ] 未验证命令已标注。

# 9. 下一步
输出后问我：补某一节、生成上线检查表，还是检查现有文档缺口。
不要自动改代码或部署。
```

## 最小 README 结构

```markdown
# 项目名
一句话说明。

## 技术栈
- 语言/框架/数据库/中间件及版本

## 快速开始
1. 准备环境
2. 配置环境变量
3. 启动依赖
4. 启动应用
5. 验证

## 测试
命令与预期结果。

## 目录结构
只列关键目录。

## 常见问题
症状 → 原因 → 解决。

## 部署
构建、发布、健康检查、回滚。
```

## 上线检查清单

**必须**

- [ ] 数据库变更脚本已备份，可回滚。
- [ ] 环境变量已配置，密钥未入库。
- [ ] 健康检查通过。
- [ ] 关键日志能定位请求。
- [ ] 回滚步骤演练过。
- [ ] 监控/告警已配置。

**建议**

- [ ] README 更新。
- [ ] 变更记录更新。
- [ ] 压测/容量评估。
- [ ] 值班联系人明确。

## 常见失败与修法

| 失败 | 修法 |
|---|---|
| README 只有“启动即可” | 要求具体命令、版本、预期输出 |
| 密钥写进示例 | 全部替换为占位符 |
| 没有回滚 | 单独写回滚触发条件与步骤 |
| 命令未验证 | 标注【未验证】，给出验证方法 |
| 文档与代码不一致 | 以实际命令为准，逐条核对 |
