# 测试设计

> 场景：为一个功能、接口或修复设计测试。
> 适用：新功能验收、bug 回归、重构安全网、上线前补测。
> 不适用：需求还没确定；先回需求澄清。
> 关键原则：**风险驱动，不追求形式上的 100% 覆盖率**。

## 可直接复制的提示词

```text
# 1. 角色与目标
你是一名务实的测试工程师，熟悉 Java/JUnit、Spring Boot Test、接口测试与边界分析。
本次唯一目标：为下面的功能/改动设计一套能发现真实问题的测试，并给出可运行用例。
目标受众：需要执行测试、判断能否上线的开发者。

# 2. 上下文
【项目卡】
{{PROJECT_CARD}}

【被测对象】
{{TASK：功能、接口、类或 bug 修复}}

【代码/契约】
{{INPUT：相关代码、接口文档、表结构、已有测试}}

# 3. 输入与前置检查
若缺少“预期行为”“输入范围”“失败时应有行为”中的任意一项，
先问我，最多 3 个问题。无法获得时，按常见契约推断并标注【假设】。

# 4. 执行步骤
1. 用一句话说明被测对象的核心契约：输入什么、保证什么、失败时怎样。
2. 识别风险：数据边界、并发、幂等、权限、事务、外部依赖、性能。
3. 按测试金字塔分配：单元测试、集成测试、端到端测试各覆盖什么。
4. 设计用例矩阵：正常、边界、异常、权限、并发/重复、回归。
5. 为每个用例写：前置条件、输入、操作、预期结果、优先级。
6. 给出可运行的测试代码或测试步骤，注明依赖与初始化数据。
7. 说明哪些情况不测、为什么；不要假装全覆盖。
8. 给出“测试通过/失败”的判定标准。

# 5. 约束与非目标
- 不追求 100% 行覆盖率；优先覆盖高风险路径。
- 测试必须可重复：不依赖真实时间、随机数、外部网络和共享状态。
- 不使用生产数据；测试数据用固定 fixture。
- 不把“能启动”当成测试通过。
- 不写只验证 mock 调用、不验证业务结果的空测试。

# 6. 输出格式
## 被测契约
## 风险清单
## 测试分层
| 层级 | 覆盖内容 | 不覆盖内容 |
## 用例矩阵
| # | 类型 | 前置 | 输入/操作 | 预期 | 优先级 |
## 测试代码/步骤
## 不测项与理由
## 通过标准
总篇幅不超过 1200 字，代码除外。

# 7. 示例
差的用例：调用接口，期望返回 200。
好的用例：
- 正常：登录用户提交 1–500 字评论，期望 201，数据库新增 1 条。
- 边界：提交 500 字，期望成功；501 字，期望 400 且不写库。
- 异常：未登录提交，期望 401，且不写库。
- 并发：同一用户并发提交两次，期望只成功一次（唯一约束生效）。
- 安全：内容含 <script>，期望存储转义或拒绝，页面不执行脚本。

# 8. 验收标准与自检
- [ ] 每个高风险点至少有一个用例。
- [ ] 正常、边界、异常路径都有覆盖。
- [ ] 用例有明确前置条件与预期结果。
- [ ] 测试可独立、可重复运行。
- [ ] 失败时能定位到具体行为，而不是只报“断言失败”。
- [ ] 明确列出不测项与理由。
- [ ] 回归用例能在修复前失败、修复后通过。

# 9. 下一步
输出后问我：先写哪一层测试、补哪个边界，还是生成测试数据。
不要一次性生成几十个低价值用例。
```

## 测试分层建议

| 层级 | 适合测什么 | 速度 | 维护成本 |
|---|---|---|---|
| 单元测试 | 纯逻辑、边界、状态转换 | 快 | 低 |
| 集成测试 | 数据库、事务、序列化、鉴权 | 中 | 中 |
| 端到端测试 | 关键用户路径、前后端联调 | 慢 | 高 |

优先把高风险逻辑下沉到单元测试；端到端只覆盖少数关键路径。

## 用例设计清单

- 正常值、最小值、最大值、空值、null、特殊字符。
- 重复提交、并发、超时、重试、部分失败。
- 未登录、越权、跨用户访问。
- 数据库唯一约束、事务回滚、软删除。
- 外部依赖不可用时的降级行为。
- 修复 bug 时：先写一个能复现的失败测试。

## 常见失败与修法

| 失败 | 修法 |
|---|---|
| 只测 happy path | 强制加边界、异常、权限三类 |
| 测试依赖真实环境 | 要求固定 fixture、mock 外部依赖 |
| 覆盖率很高但没断言 | 要求每个测试至少一个业务结果断言 |
| 并发测试不稳定 | 用可控的 latch/事务隔离，不用 sleep |
| 回归测试不能复现 bug | 先确认测试在修复前确实失败 |

## 通过标准示例

```text
功能测试：全部 P0/P1 用例通过。
回归测试：修复前失败的用例，修复后通过。
稳定性：并发用例连续运行 10 次无偶发失败。
安全：XSS/越权用例通过。
未测项：真实支付网关、生产规模性能；上线前单独验证。
```
