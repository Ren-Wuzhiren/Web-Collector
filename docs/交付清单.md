# WebCollector v0.1.0 交付清单

> **一句话**：本文列出本地自托管 MVP 的交付物、启动步骤、管理员保留方式、备份恢复和已知边界。🐋

## 版本与适用范围

| 项目 | 内容 |
|---|---|
| 产品版本 | `v0.1.0` |
| 形态 | 单人本地 Docker Compose 自托管 |
| 正式入口 | `http://localhost:8080` |
| 核心能力 | 保存 URL、HTML/PDF/截图、正文、集合、标签、搜索和管理员运营 |
| 不包含 | 公网域名、TLS、外部主机部署、协作、分享和浏览器扩展 |

## 交付物

- Spring Boot 后端、Vue 前端和 Flyway V1–V17 数据库迁移。
- Docker Compose、Nginx、Dockerfile 和 `.env.example`。
- 真实 URL、备份恢复、演示账号和管理员提升脚本。
- 架构、数据库、接口、测试、运维、验收、复盘和四大件笔记。
- M9.1 30 个真实 URL 的最终合并验收单及原始本地证据索引。

## 首次启动

1. 把 `deploy/.env.example` 复制为 `deploy/.env`。
2. 替换 MySQL、Redis 的占位密码，并确认 `REGISTRATION_ENABLED=true`。
3. 从仓库根目录启动：

```powershell
docker compose -p webcollector --env-file .\deploy\.env `
  -f .\deploy\docker-compose.yml up -d --build
docker compose -p webcollector --env-file .\deploy\.env `
  -f .\deploy\docker-compose.yml ps
```

4. 检查首页和健康接口：

```powershell
curl.exe http://127.0.0.1:8080/
curl.exe http://127.0.0.1:8080/api/v1/health/live
curl.exe http://127.0.0.1:8080/api/v1/health/ready
```

## 管理员保留

首次使用时通过网页注册专用账号 `admin`，密码由你本人设置并存放在密码管理器中。

```powershell
.\scripts\promote-admin.ps1 `
  -Username admin `
  -ComposeFile .\deploy\docker-compose.yml `
  -EnvFile .\deploy\.env `
  -ProjectName webcollector
```

确认 `/admin` 可访问后，把 `deploy/.env` 中的 `REGISTRATION_ENABLED` 改为 `false` 并重建 backend。

管理员账号保存在 `webcollector_mysql_data`。正常停止只执行不带 `-v` 的 Compose `down`；`down -v` 会删除数据库、Redis 和资产数据卷。

## 备份与恢复

```powershell
.\deploy\backup.ps1 `
  -ProjectName webcollector `
  -ComposeFile .\deploy\docker-compose.yml `
  -EnvFile .\deploy\.env `
  -OutputRoot .\.superpowers\v0.1.0\backups
```

恢复前先停止写入并确认备份目录、项目名和清单哈希。恢复命令与完整失败边界见 `deploy/README.md`。

## 升级与回滚

1. 升级前创建基线备份。
2. 拉取或切换到目标版本，执行 `up -d --build`。
3. 验证 live、ready、首页、登录和管理员页面。
4. 失败时切回上一版本提交并重新构建；数据库迁移回滚必须先评估，不能直接删除数据卷。

## 已知限制

- 公网域名、TLS、反向代理链和真实公网攻击面未验证。
- 当前 Windows 环境有 4 个符号链接防护测试跳过，需在支持符号链接的 Linux CI 补跑。
- CI 只运行后端测试和前端生产构建，不运行 Playwright、视觉门禁和真实 URL 抓取。
- 前端生产构建存在既有大 chunk 警告。
- M9.1 的正向与负向证据来自不同运行和不同一次性账号，不是单轮连续 30 项。
