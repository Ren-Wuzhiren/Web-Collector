#### 1. 涉及技术栈（为什么是它）

| 技术/组件 | 用在哪 | 为什么选它 | 备选 & 不选的理由 |
|---|---|---|---|
| Spring MVC | `GET /api/v1/links/{id}/readable` | 复用现有 Controller、鉴权和统一响应 | 直接返回 raw `text/plain` 会绕开项目现有 `ApiResponse` 契约 |

| JUnit 5 + Mockito + MockMvc | 后续单元和 HTTP 测试 | 项目已统一使用，可分别验证业务映射与响应契约 | 只测 Mapper 无法证明 Service 真的绑定当前用户 |

#### 2. 原理讲解（不用它会怎样）

- **对象级授权**：查询链接时同时绑定 `link.id` 和当前会话的 `user_id`。不用它时，知道他人链接 ID 就能读走私人正文。
- **统一 404**：链接不存在、不属于当前用户时都返回 `404 NOT_FOUND`。不用它时，`403` 与 `404` 的差异会帮助攻击者枚举哪些链接真实存在。
- **单一正文来源**：阅读接口直接使用 M4.3 已写入的 `link.text_content`。不用它而再从 HTML 临时抽取，会让“搜索正文”和“阅读正文”出现两套处理规则。
- **JSON 文本边界**：正文作为字符串进入 JSON，前端使用文本绑定。把它伪装成 HTML 返回，会让不可信页面内容进入应用同源执行环境。

#### 3. 架构讲解（这一步在整体里占哪个位置）

- **分层位置**：`ReadableLinkController → ReadableLinkService → LinkMapper → MySQL`。
- **数据流向**：

```text
GET /api/v1/links/{id}/readable
  → Controller 绑定 linkId
  → Service 从 Sa-Token 会话读取 userId
  → LinkMapper 按 id + user_id 查询 Link
  → 检查 text_content 是否存在且非空白
  → 组装 LinkSummary + textContent
  → ApiResponse<ReadableLinkResponse> 返回 JSON
```

- **改动边界**：新增响应 DTO、Service、Controller 三个文件；不修改现有 Controller、Service、Mapper、数据库或资产存储，不读取原始 `page.html`。
- **为什么放这层**：Controller 只负责 HTTP 绑定和包装；用户身份与正文可用性属于业务规则，必须在 Service 中执行。若授权写进 Controller，将来其他入口可以直接绕过它。

#### 5. 重难语法讲解

- **`new LambdaQueryWrapper<Link>().eq(...)`**：`eq(Link::getId, linkId)` 和 `eq(Link::getUserId, userId)` 会生成两个 `AND` 条件。漏掉 user 条件时，查询仍能找到链接，但会直接造成越权。
- **`String.isBlank()`**：同时识别空串、空格和换行。只写 `isEmpty()` 会把全空白正文当作可用正文。校验只用 `isBlank()`，返回时不要 `trim()`，否则段落首尾空白会被改写。
- **`LinkSummary + textContent` record DTO**：复用现有 `LinkSummary` 的时间格式和字段定义，避免再维护一套几乎相同的元数据字段。直接返回 `Link` 实体会把 `userId`、`urlHash` 等内部字段暴露给客户端。
- **`ApiResponse.success(...)`**：统一成功响应的 `data`、`message`、`requestId`。阅读接口不设置 raw HTML 的 `Content-Type`，因此浏览器不会把它当页面执行。

##### `backend/src/main/java/com/webcollector/link/service/ReadableLinkService.java`

- **作用**：校验链接所有权和正文可用性，并组装阅读响应。
- **完整代码**：

```java
package com.webcollector.link.service;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.webcollector.auth.session.SessionTokenService;
import com.webcollector.common.web.BusinessException;
import com.webcollector.common.web.ErrorCode;
import com.webcollector.link.dto.LinkSummary;
import com.webcollector.link.dto.ReadableLinkResponse;
import com.webcollector.link.entity.Link;
import com.webcollector.link.mapper.LinkMapper;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.time.ZoneOffset;

/**
 * 读取当前用户链接清理正文的用例。
 */
@Service
public class ReadableLinkService {
    private final LinkMapper linkMapper;
    private final SessionTokenService sessionTokenService;

    public ReadableLinkService(
            LinkMapper linkMapper,
            SessionTokenService sessionTokenService
    ) {
        this.linkMapper = linkMapper;
        this.sessionTokenService = sessionTokenService;
    }

    /**
     * 读取本人链接的清理正文。
     *
     * <p>[业务] 查询同时绑定 linkId 与当前 userId。链接不存在、不属于当前用户
     * 或正文尚未生成时统一返回 404，避免泄露其他用户链接是否存在。</p>
     */
    @Transactional(readOnly = true)
    public ReadableLinkResponse getReadableLink(Long linkId) {
        Long userId = sessionTokenService.requireLoginId();

        Link link = linkMapper.selectOne(
                new LambdaQueryWrapper<Link>()
                        .eq(Link::getId, linkId)
                        .eq(Link::getUserId, userId)
        );

        if (link == null) {
            throw new BusinessException(ErrorCode.NOT_FOUND);
        }

        String textContent = link.getTextContent();
        if (textContent == null || textContent.isBlank()) {
            throw new BusinessException(
                    ErrorCode.NOT_FOUND,
                    "正文尚未生成"
            );
        }

        return new ReadableLinkResponse(toSummary(link), textContent);
    }

    private LinkSummary toSummary(Link link) {
        return new LinkSummary(
                link.getId(),
                link.getCollectionId(),
                link.getOriginalUrl(),
                link.getTitle(),
                link.getDescription(),
                link.getCreatedAt().toInstant(ZoneOffset.UTC),
                link.getUpdatedAt().toInstant(ZoneOffset.UTC)
        );
    }
}
```

- **关键 3 行**：`.eq(Link::getUserId, userId)` 提供对象级授权；`textContent == null || textContent.isBlank()` 阻止空正文进入成功响应；`return new ReadableLinkResponse(toSummary(link), textContent)` 原样携带正文，不改写段落。
- **怎么验证**：本人链接的 `text_content` 非空时返回 200；他人链接返回 404；本人链接正文为空串、空格或换行时返回 404 和“正文尚未生成”。

##### `backend/src/main/java/com/webcollector/link/controller/ReadableLinkController.java`

- **作用**：提供稳定阅读端点并包装统一响应。
- **完整代码**：

```java
package com.webcollector.link.controller;

import com.webcollector.common.web.ApiResponse;
import com.webcollector.link.dto.ReadableLinkResponse;
import com.webcollector.link.service.ReadableLinkService;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

/**
 * 链接清理正文阅读接口。
 */
@RestController
@RequestMapping("/api/v1/links")
public class ReadableLinkController {
    private final ReadableLinkService readableLinkService;

    public ReadableLinkController(
            ReadableLinkService readableLinkService
    ) {
        this.readableLinkService = readableLinkService;
    }

    @GetMapping("/{id}/readable")
    public ApiResponse<ReadableLinkResponse> getReadableLink(
            @PathVariable("id") Long linkId
    ) {
        return ApiResponse.success(
                readableLinkService.getReadableLink(linkId)
        );
    }
}
```

- **关键 3 行**：路由固定为 `/api/v1/links/{id}/readable`；Controller 只把路径 id 交给 Service；响应使用 `ApiResponse<ReadableLinkResponse>`，不直接返回 HTML 流。
- **怎么验证**：启动应用后携带 Bearer Token 请求本人链接，期望返回 `application/json` 和 `data.link`、`data.textContent`。

#### 8. 坑（会怎么错，不是要注意什么）

- ❌ 只按 `linkId` 查链接，再用 Java 判断 owner → 某条异常分支可能忘记比较 → 查询条件必须同时带 `id` 和当前会话 `userId`。
- ❌ 用 `textContent.isEmpty()` 判断正文 → 全是空格或换行的正文会被当成功响应 → 使用 `isBlank()`。
- ❌ 返回前执行 `textContent.trim()` → 正文段落首尾被改写 → 只检查空白，成功响应原样返回。
- ❌ 直接返回 `Link` 实体 → `userId`、URL hash 等内部字段泄漏 → 使用 `ReadableLinkResponse`。
- ❌ 把 `textContent` 塞进 HTML 或前端 `v-html` → 不可信文本进入页面执行上下文 → 使用 JSON 字符串和文本绑定。

**能讲（Codex 先给参考回答，用户随后凭记忆复述）**

- [ ] Q1：为什么查询条件不能只写 `link.id`，然后在 Java 里判断 `link.userId == 当前用户`？

  > **参考回答**：客户端可以拿到或猜测链接 ID，ID 本身不是权限凭证。查询同时绑定 `id` 和当前会话 `user_id`，数据库只返回当前用户范围内的对象；这样授权是查询成立的前提，不依赖调用方记得在后续某个分支比较 owner。链接不存在和不是本人时又统一返回 404，避免泄露对象是否存在。

- [ ] Q2：为什么这里返回 JSON 中的纯文本，而不是把 M4.3 清洗后的 HTML 直接作为页面返回？

  > **参考回答**：当前真正落库的是 `link.text_content`，它是纯文本；接口把正文作为 JSON 字符串交给前端，前端用文本绑定展示即可。直接返回 HTML 会把不可信网页内容带进应用同源上下文，后续很容易误用 `v-html` 或内联脚本。纯文本牺牲少量富文本样式，换来了更清晰的信任边界。
