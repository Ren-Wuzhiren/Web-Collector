### 二级阶段 M3.3：失败重试与锁超时恢复

**一句话**：任务失败后按退避时间再次排队，Worker 崩溃留下的过期任务也能重新可见。
**完成标志**：前两次失败分别在 30 秒、120 秒后重试，第三次失败进入终态；过期锁能恢复或按次数终结。
**实施状态（2026-10-25）**：工程实现、自动化验收与学习验收均已完成；全量测试 236 项通过。
**预计时长**：一次实现会话　**依赖**：M3.2 已完成

---

#### 1. 涉及技术栈（为什么是它）

| 技术/组件 | 用在哪 | 为什么选它 | 备选 & 不选的理由 |
|---|---|---|---|
| MySQL 条件更新 | 失败重试、超时恢复和终态判断 | 状态、尝试次数与下一执行时间在一行内原子修改 | 先读再改会让两个收尾调用互相覆盖 |
| `FOR UPDATE SKIP LOCKED` | 批量找回过期租约 | 多个恢复调用各取一批，不阻塞正在变化的任务 | Redis 锁需要与 MySQL 状态双写，容易不一致 |
| Spring `@Transactional` | 恢复一批任务 | 锁定候选行、决定 PENDING/FAILED、更新字段同成同败 | 把整批查询与更新拆开，锁会提前释放 |

#### 2. 原理讲解（不用它会怎样）

- **退避重试**：失败后不立刻重跑，而是把 `next_attempt_at` 推到未来。不用它：目标站点持续超时时，Worker 会立刻反复请求，放大故障。
- **次数上限**：`attempt_count` 在领取时递增，失败时读取它决定重试还是终结。不用它：永久失败的任务会无限循环。
- **租约恢复**：`RUNNING` 且 `locked_until <= now` 表示持有者可能崩溃。未到上限就回 `PENDING`，到上限则 `FAILED`。不用它：进程崩溃后任务永远卡在 `RUNNING`。
- **条件更新**：所有收尾都带 `WHERE status='RUNNING'`。不用它：旧 Worker 在任务已被恢复后仍可覆盖新状态。

#### 3. 架构讲解（这一步在整体里占哪个位置）

- **分层位置**：`未来的 Worker / M3.4 调度调用 → CaptureJobService → CaptureJobMapper → MySQL`。
- **失败数据流**：

```text
fail(jobId, errorCode, errorMessage)
  → 读取 RUNNING 任务的 attempt_count / max_attempts
  → attempt_count < max_attempts
      → PENDING, next_attempt_at = now + 30/120 秒
  → 已达到 max_attempts
      → FAILED, finished_at = now
  → PENDING/FAILED 两种结果都清理租约并记录最近错误
```

- **恢复数据流**：

```text
recoverExpiredJobs()
  → SELECT id ... RUNNING AND locked_until <= now
      ORDER BY locked_until, id
      LIMIT 100
      FOR UPDATE SKIP LOCKED
  → 未到上限：PENDING, next_attempt_at = now
  → 达到上限：FAILED, finished_at = now
```

- **改动边界**：修改状态白名单、Mapper 和 CaptureJobService；不新增迁移、Controller、`@Scheduled`、假 Worker或手动重采集。

#### 5. 重难语法讲解

- **`LocalDateTime.plus(Duration)`**
  - 标准写法：`now.plus(FIRST_RETRY_DELAY)`。
  - 参数含义：`Duration.ofSeconds(30)` 表示未来 30 秒，不包含时区。
  - 常见错法：用 `Thread.sleep(30_000)` 等重试。它只阻塞当前线程，进程重启后时间信息就丢了。
- **批量锁定查询**
  - 标准写法：`ORDER BY locked_until, id LIMIT #{limit} FOR UPDATE SKIP LOCKED`。
  - 参数含义：`limit` 控制单个事务处理的恢复数量，初版固定 100。
  - 常见错法：一次恢复全表。大事务会延迟 Worker 领取并扩大锁等待。
- **条件更新**
  - 标准写法：更新时再次带 `status='RUNNING' AND locked_until <= #{now}`。
  - 参数含义：即使调用方判断过状态，数据库仍要在真正修改时复核。
  - 常见错法：只按 `id` 更新，旧 Worker 可能覆盖已经恢复的任务。

```java
package com.webcollector.capture.entity;

/**
 * [业务] 抓取任务的状态取值，与 V9 里 status 列的 ENUM 一一对应。
 */
public enum CaptureJobStatus {
    PENDING,
    RUNNING,
    SUCCEEDED,
    FAILED;

    /**
     * [业务] 允许的迁移是显式白名单，不在白名单中的跳转一律拒绝。
     *
     * [408] RUNNING→PENDING 表示失败后仍有尝试次数；
     * FAILED→PENDING 留给 M3.4 的手动重新采集，本步不放行。
     */
    public boolean canTransitionTo(CaptureJobStatus target) {
        if (target == null || target == this) {
            return false;
        }

        return switch (this) {
            case PENDING -> target == RUNNING;
            case RUNNING -> target == PENDING
                    || target == SUCCEEDED
                    || target == FAILED;
            case SUCCEEDED, FAILED -> false;
        };
    }
}
```

```java
package com.webcollector.capture.mapper;

import com.baomidou.mybatisplus.core.mapper.BaseMapper;
import com.webcollector.capture.entity.CaptureJob;
import org.apache.ibatis.annotations.Param;
import org.apache.ibatis.annotations.Select;
import org.apache.ibatis.annotations.Update;

import java.time.LocalDateTime;
import java.util.List;

/**
 * [软件工程] 普通持久化操作复用 BaseMapper；需要行锁、SKIP LOCKED、
 * 字段原子增减或批量恢复的查询使用原生 SQL。
 */
public interface CaptureJobMapper extends BaseMapper<CaptureJob> {

    @Select("""
            SELECT id
            FROM capture_job
            WHERE status = 'PENDING'
              AND next_attempt_at <= #{now}
            ORDER BY next_attempt_at, id
            LIMIT 1
            FOR UPDATE SKIP LOCKED
            """)
    Long selectNextClaimableJobId(@Param("now") LocalDateTime now);

    @Update("""
            UPDATE capture_job
            SET status = 'RUNNING',
                attempt_count = attempt_count + 1,
                locked_by = #{workerId},
                locked_until = #{lockedUntil},
                started_at = #{now},
                updated_at = #{now}
            WHERE id = #{jobId}
              AND status = 'PENDING'
            """)
    int claimPendingJob(
            @Param("jobId") Long jobId,
            @Param("workerId") String workerId,
            @Param("now") LocalDateTime now,
            @Param("lockedUntil") LocalDateTime lockedUntil
    );

    /**
     * [业务] 锁定一批租约已经过期的 RUNNING 任务。
     */
    @Select("""
            SELECT id
            FROM capture_job
            WHERE status = 'RUNNING'
              AND locked_until IS NOT NULL
              AND locked_until <= #{now}
            ORDER BY locked_until, id
            LIMIT #{limit}
            FOR UPDATE SKIP LOCKED
            """)
    List<Long> selectExpiredRunningJobIds(
            @Param("now") LocalDateTime now,
            @Param("limit") int limit
    );

    /**
     * [业务] 租约过期但仍可重试：立即回到 PENDING。
     */
    @Update("""
            UPDATE capture_job
            SET status = 'PENDING',
                next_attempt_at = #{now},
                locked_by = NULL,
                locked_until = NULL,
                finished_at = NULL,
                error_code = #{errorCode},
                error_message = #{errorMessage},
                updated_at = #{now}
            WHERE id = #{jobId}
              AND status = 'RUNNING'
              AND locked_until IS NOT NULL
              AND locked_until <= #{now}
            """)
    int requeueExpiredJob(
            @Param("jobId") Long jobId,
            @Param("now") LocalDateTime now,
            @Param("errorCode") String errorCode,
            @Param("errorMessage") String errorMessage
    );

    /**
     * [业务] 租约过期且尝试次数已耗尽：进入 FAILED。
     */
    @Update("""
            UPDATE capture_job
            SET status = 'FAILED',
                locked_by = NULL,
                locked_until = NULL,
                finished_at = #{now},
                error_code = #{errorCode},
                error_message = #{errorMessage},
                updated_at = #{now}
            WHERE id = #{jobId}
              AND status = 'RUNNING'
              AND locked_until IS NOT NULL
              AND locked_until <= #{now}
            """)
    int failExpiredJob(
            @Param("jobId") Long jobId,
            @Param("now") LocalDateTime now,
            @Param("errorCode") String errorCode,
            @Param("errorMessage") String errorMessage
    );
}
```

##### `backend/src/main/java/com/webcollector/capture/service/CaptureJobService.java`

```java
package com.webcollector.capture.service;

import com.baomidou.mybatisplus.core.conditions.update.LambdaUpdateWrapper;
import com.webcollector.capture.dto.CaptureJobSummary;
import com.webcollector.capture.entity.CaptureJob;
import com.webcollector.capture.entity.CaptureJobStatus;
import com.webcollector.capture.mapper.CaptureJobMapper;
import com.webcollector.common.web.BusinessException;
import com.webcollector.common.web.ErrorCode;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.time.Clock;
import java.time.Duration;
import java.time.LocalDateTime;
import java.time.ZoneOffset;
import java.time.temporal.ChronoUnit;
import java.util.List;
import java.util.Optional;

/**
 * [业务] 抓取任务的创建、领取、失败重试、终态收尾与锁超时恢复入口。
 */
@Service
public class CaptureJobService {
    private static final int DEFAULT_MAX_ATTEMPTS = 3;
    private static final int MAX_WORKER_ID_LENGTH = 100;
    private static final int RECOVERY_BATCH_SIZE = 100;
    private static final Duration FIRST_RETRY_DELAY = Duration.ofSeconds(30);
    private static final Duration SECOND_RETRY_DELAY = Duration.ofSeconds(120);
    private static final String LEASE_EXPIRED_ERROR_CODE = "WORKER_LEASE_EXPIRED";
    private static final String LEASE_EXPIRED_ERROR_MESSAGE = "Worker 租约已过期";

    private final CaptureJobMapper captureJobMapper;
    private final Clock clock;

    public CaptureJobService(CaptureJobMapper captureJobMapper, Clock clock) {
        this.captureJobMapper = captureJobMapper;
        this.clock = clock;
    }

    @Transactional
    public CaptureJobSummary createPending(Long linkId, Long requestedBy, LocalDateTime now) {
        CaptureJob job = new CaptureJob();
        job.setLinkId(linkId);
        job.setRequestedBy(requestedBy);
        job.setStatus(CaptureJobStatus.PENDING);
        job.setAttemptCount(0);
        job.setMaxAttempts(DEFAULT_MAX_ATTEMPTS);
        job.setNextAttemptAt(now);
        job.setCreatedAt(now);
        job.setUpdatedAt(now);

        captureJobMapper.insert(job);
        return toSummary(job);
    }

    @Transactional
    public Optional<CaptureJobSummary> claimNext(
            String workerId,
            LocalDateTime lockedUntil
    ) {
        LocalDateTime now = now();
        LocalDateTime leaseEnd = validateClaimParameters(workerId, lockedUntil, now);
        Long jobId = captureJobMapper.selectNextClaimableJobId(now);

        if (jobId == null) {
            return Optional.empty();
        }

        return Optional.of(claimPendingJob(jobId, workerId, now, leaseEnd));
    }

    @Transactional
    public CaptureJobSummary claim(
            Long jobId,
            String workerId,
            LocalDateTime lockedUntil
    ) {
        LocalDateTime now = now();
        LocalDateTime leaseEnd = validateClaimParameters(workerId, lockedUntil, now);
        return claimPendingJob(jobId, workerId, now, leaseEnd);
    }

    /**
     * [业务] 成功终态会清除之前重试留下的错误信息。
     */
    @Transactional
    public CaptureJobSummary complete(Long jobId) {
        LocalDateTime now = now();

        int updated = captureJobMapper.update(
                null,
                new LambdaUpdateWrapper<CaptureJob>()
                        .eq(CaptureJob::getId, jobId)
                        .eq(CaptureJob::getStatus, CaptureJobStatus.RUNNING)
                        .set(CaptureJob::getStatus, CaptureJobStatus.SUCCEEDED)
                        .set(CaptureJob::getFinishedAt, now)
                        .set(CaptureJob::getUpdatedAt, now)
                        .set(CaptureJob::getLockedBy, null)
                        .set(CaptureJob::getLockedUntil, null)
                        .set(CaptureJob::getErrorCode, null)
                        .set(CaptureJob::getErrorMessage, null)
        );

        if (updated == 0) {
            throw transitionFailure(jobId);
        }

        return toSummary(requireJob(jobId));
    }

    /**
     * [业务] 失败后根据已经消耗的尝试次数决定重试或终结。
     */
    @Transactional
    public CaptureJobSummary fail(Long jobId, String errorCode, String errorMessage) {
        CaptureJob job = requireJob(jobId);
        LocalDateTime now = now();
        CaptureJobStatus target = job.getAttemptCount() < job.getMaxAttempts()
                ? CaptureJobStatus.PENDING
                : CaptureJobStatus.FAILED;

        if (!job.getStatus().canTransitionTo(target)) {
            throw new BusinessException(ErrorCode.CAPTURE_JOB_INVALID_STATE);
        }

        LambdaUpdateWrapper<CaptureJob> update = new LambdaUpdateWrapper<CaptureJob>()
                .eq(CaptureJob::getId, jobId)
                .eq(CaptureJob::getStatus, CaptureJobStatus.RUNNING)
                .set(CaptureJob::getStatus, target)
                .set(CaptureJob::getErrorCode, errorCode)
                .set(CaptureJob::getErrorMessage, errorMessage)
                .set(CaptureJob::getUpdatedAt, now)
                .set(CaptureJob::getLockedBy, null)
                .set(CaptureJob::getLockedUntil, null);

        if (target == CaptureJobStatus.PENDING) {
            update.set(
                    CaptureJob::getNextAttemptAt,
                    now.plus(retryDelayForAttempt(job.getAttemptCount()))
            );
            update.set(CaptureJob::getFinishedAt, null);
        } else {
            update.set(CaptureJob::getFinishedAt, now);
        }

        int updated = captureJobMapper.update(null, update);

        if (updated == 0) {
            throw transitionFailure(jobId);
        }

        return toSummary(requireJob(jobId));
    }

    /**
     * [业务] 找回租约过期但未终态的任务，单次最多处理 100 条。
     *
     * [数据库] SELECT 与后续 UPDATE 处于同一事务；SKIP LOCKED 允许
     * 多个恢复调用各处理不同批次，不会重复领取同一行。
     */
    @Transactional
    public int recoverExpiredJobs() {
        LocalDateTime now = now();
        List<Long> jobIds = captureJobMapper.selectExpiredRunningJobIds(
                now,
                RECOVERY_BATCH_SIZE
        );
        int recovered = 0;

        for (Long jobId : jobIds) {
            CaptureJob job = requireJob(jobId);
            int updated;

            if (job.getAttemptCount() < job.getMaxAttempts()) {
                updated = captureJobMapper.requeueExpiredJob(
                        jobId,
                        now,
                        LEASE_EXPIRED_ERROR_CODE,
                        LEASE_EXPIRED_ERROR_MESSAGE
                );
            } else {
                updated = captureJobMapper.failExpiredJob(
                        jobId,
                        now,
                        LEASE_EXPIRED_ERROR_CODE,
                        LEASE_EXPIRED_ERROR_MESSAGE
                );
            }

            recovered += updated;
        }

        return recovered;
    }

    private CaptureJobSummary claimPendingJob(
            Long jobId,
            String workerId,
            LocalDateTime now,
            LocalDateTime lockedUntil
    ) {
        int updated = captureJobMapper.claimPendingJob(
                jobId,
                workerId,
                now,
                lockedUntil
        );

        if (updated == 0) {
            throw transitionFailure(jobId);
        }

        return toSummary(requireJob(jobId));
    }

    private Duration retryDelayForAttempt(int attemptCount) {
        return attemptCount <= 1 ? FIRST_RETRY_DELAY : SECOND_RETRY_DELAY;
    }

    private LocalDateTime validateClaimParameters(
            String workerId,
            LocalDateTime lockedUntil,
            LocalDateTime now
    ) {
        if (workerId == null || workerId.isBlank()) {
            throw new IllegalArgumentException("workerId 不能为空");
        }

        if (workerId.length() > MAX_WORKER_ID_LENGTH) {
            throw new IllegalArgumentException("workerId 不能超过 100 个字符");
        }

        if (lockedUntil == null) {
            throw new IllegalArgumentException("lockedUntil 不能为空");
        }

        LocalDateTime leaseEnd = lockedUntil.truncatedTo(ChronoUnit.MILLIS);

        if (!leaseEnd.isAfter(now)) {
            throw new IllegalArgumentException("lockedUntil 必须晚于当前时间");
        }

        return leaseEnd;
    }

    private BusinessException transitionFailure(Long jobId) {
        return captureJobMapper.selectById(jobId) == null
                ? new BusinessException(ErrorCode.NOT_FOUND)
                : new BusinessException(ErrorCode.CAPTURE_JOB_INVALID_STATE);
    }

    private CaptureJob requireJob(Long jobId) {
        CaptureJob job = captureJobMapper.selectById(jobId);

        if (job == null) {
            throw new BusinessException(ErrorCode.NOT_FOUND);
        }

        return job;
    }

    private LocalDateTime now() {
        return LocalDateTime.now(clock).truncatedTo(ChronoUnit.MILLIS);
    }

    private CaptureJobSummary toSummary(CaptureJob job) {
        return new CaptureJobSummary(
                job.getId(),
                job.getLinkId(),
                job.getStatus(),
                job.getAttemptCount(),
                job.getNextAttemptAt().toInstant(ZoneOffset.UTC)
        );
    }
}
```

#### 7. 计算机四大件映射

- **映射到**：操作系统。
- **具体机制**：租约是带截止时间的互斥所有权，过期后由恢复者重新放入可运行队列；`SKIP LOCKED` 避免多个恢复线程阻塞在同一临界区。

#### 8. 坑（会怎么错，不是要注意什么）

- ❌ 用 `Thread.sleep` 等待重试 → 应用重启后等待状态全部丢失 → 持久化 `next_attempt_at`。
- ❌ 所有失败都直接 `FAILED` → 偶发网络错误没有恢复机会 → 前两次回 `PENDING`。
- ❌ 所有失败都无限重试 → 永久坏地址让队列永远不空 → 读取 `max_attempts` 限制次数。
- ❌ 恢复时保留旧 `locked_by` / `locked_until` → 任务重新排队后仍带着旧租约 → 两种恢复都清空。
- ❌ 旧 Worker 在恢复后继续 `complete` → 覆盖新任务状态 → 条件更新必须复核 `status='RUNNING'`。
- ❌ 本轮顺手加 `@Scheduled` → 应用启动方式、测试隔离和 M3.4 边界被打乱 → 只提供可调用的 Service。

**能讲（Codex 先示范，用户随后合上材料作答）**
- [x] Q1：为什么重试时间要写进 `next_attempt_at`，而不是让 Worker 睡眠等待？

  > **参考示范**：`next_attempt_at` 是数据库里的持久化调度事实，进程重启后仍然存在，其他 Worker 也可以接手；`Thread.sleep` 只占住当前线程，重启就丢失等待状态，还会浪费线程资源。

  > 我的回答：next_attempt_at可以用于数据持久化调度，进程重启之后不会直接消失，贸然重启会丢失等待状态，还会浪费线程资源。

  > 差距提示：核心意思正确；“贸然重启”应明确为“进程重启”，并补充其他 Worker 可以接手到期任务。

- [x] Q2：租约过期后旧 Worker 又调用 `complete`，系统怎样避免它覆盖新状态？

  > **参考示范**：恢复和旧 Worker 的更新都带行锁与条件。若恢复先提交，任务已变成 `PENDING` 或 `FAILED`，旧 Worker 的 `WHERE status='RUNNING'` 更新影响 0 行并返回 409；若旧 Worker 先完成，恢复查询就看不到过期 `RUNNING` 行。

  > 我的回答：先提交恢复，把PENDING状态变成FAILED，这样就可以把错误码409从服务端端返回客户端。

  > 差距提示：抓到了“恢复先提交后旧 Worker 得到 409”，但恢复未必变成 `FAILED`，尝试次数未耗尽时会变为 `PENDING`；关键机制是旧 Worker 的条件更新影响 0 行。
