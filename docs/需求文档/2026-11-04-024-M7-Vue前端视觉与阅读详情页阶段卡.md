# M7 Vue 前端视觉与阅读详情页阶段卡

> 状态：M7 工程与自动化验收完成，学习验收待用户回答。链接标签读取、详情页、E2E、`ArchiveCounter`、View Transitions 和三档视觉门禁均已完成。
> 方向来源：`design-taste-frontend` 的 `Achromatic ledger`，seed `112099372`。
> 动效来源：React Bits 官方 Vue 移植版 Vue Bits 的 `Counter`，本地改造为 `ArchiveCounter`。

## 方案结论

**一句话**：把 WebCollector 从“基础 Element Plus 管理页”改成一套以“保存证据”为核心的个人档案工作台，并补齐链接详情、正文阅读、标签整理和浏览器 E2E。

**完成标志**：用户登录后能保存网页、看到抓取状态、按集合整理收藏、进入详情读取纯文本正文、查看 HTML/PDF/截图证据、编辑标签；搜索和标签管理可用；在 1440、768、390 三个宽度下通过设计与功能验收。

### 目标

- 完成 M7 所需的登录、收藏、保存、进度、详情、阅读、搜索和标签闭环。
- 让“保存当时的内容仍然可读、可核验”成为产品最强视觉与交互特征。
- 保留 Vue 3 + Vite + Pinia + Vue Router + Element Plus，不迁移 React，不引入 Tailwind。
- 让前端在无数据、抓取中、部分失败、无正文和接口失败时仍能给出可信状态。
- 用真实数据完成个人作品集级界面，不制造虚假的统计、用户评价或业务指标。

### 非目标

- 不做公开分享、协作权限、深色主题、浏览器扩展、手动重新采集或移动原生应用。
- 不新增集合 CRUD 页面；“整理收藏”本轮通过集合选择和筛选实现。
- 不新增数据库表、迁移、资产类型或新的任务状态。
- 不把 HTML 快照嵌入当前 Vue 页面，也不使用 `v-html` 渲染正文。
- 不使用粒子背景、光标拖尾、滚动劫持、渐变光晕或大面积玻璃效果。

### 反目标

以下情况即使页面“能跑”也算失败：

- 第一屏只像通用后台模板，看不出这是保存网页证据的系统。
- 为了视觉冲击而隐藏正文、把重要信息压到假图表里，或使用假数据填空。
- 通过前端颜色或图标伪造抓取成功，实际资产或正文尚未生成。
- 功能正确，但手机端仍保留桌面侧栏、表格横向溢出或小于 44px 的触控目标。

## 1. 涉及技术栈（为什么是它）

| 技术/组件 | 用在哪 | 为什么选它 | 备选 & 不选的理由 |
|---|---|---|---|
| Vue 3 + Vite | 全部前端页面、路由和构建 | 仓库已有可构建前端，改动可以继续沿用 | React：只为使用 React Bits 就重写路由、状态和页面，成本与回归面过大 |
| Vue Router | `/links`、`/links/:id`、`/search`、`/tags` | 现有鉴权守卫已基于路由工作 | 单页条件渲染：深链接、刷新和浏览器返回都会变差 |
| Pinia | 登录用户、集合/标签目录缓存 | 已有 auth store，目录状态适合跨页面共享 | 每页重复请求：详情、搜索和保存面板会重复拉取集合与标签 |
| Element Plus | 表单、选择器、抽屉、对话框、消息提示 | 保留现有交互基础，减少无意义重写 | 完全手写控件：无障碍、焦点和校验成本更高 |
| 全局 CSS tokens | 颜色、字体、间距、圆角、状态 | 让视觉系统集中维护，清除默认蓝和散落样式 | 组件内硬编码：同一颜色与间距会逐渐分叉 |
| Noto Sans SC / Noto Serif SC | 中英文 UI / 阅读正文 | 自托管保证离线环境稳定，衬线只服务阅读内容 | Geist：缺少中文字形；系统字体：跨平台观感不可控 |
| Vue Bits `Counter` + `motion-v` | 收藏、集合、标签数量的变化反馈 | 官方 Vue 实现，单组件依赖较轻，符合已选动效边界 | React Bits 直接接入：不能进 Vue；其他背景或光标组件：干扰阅读工具 |
| Playwright | M7 浏览器闭环验收 | 能覆盖真实登录、保存、轮询、搜索、详情和越权路径 | 只做构建：无法证明浏览器内闭环真的可用 |
| Spring MVC + MyBatis-Plus | 新增 `GET /links/{id}/tags` | 复用现有鉴权、所有权和标签模型，不需要数据库改动 | 把标签塞进 `LinkSummary`：列表和搜索会为每行多查标签，放大 N+1 |

## 2. 原理讲解（不用它会怎样）

- **【异步证据链】**：保存链接和生成快照是两个时间尺度不同的动作。页面必须在 `PENDING → RUNNING → SUCCEEDED/FAILED` 之间显示真实进度，不能把“已创建任务”说成“已经保存完成”。不用它会怎样：用户刚保存就离开，随后看到空资产区，会误判系统数据丢失。
- **【证据分离】**：正文、HTML、PDF、截图是四种不同可信度和用途的副本。正文用于阅读，HTML/PDF/截图用于回看当时页面；它们不能合成一个模糊的“附件”列表。不用它会怎样：用户无法判断当前看到的是系统清洗文本，还是原始网页副本。
- **【文本信任边界】**：抓取正文来自不受信任网页，只能作为文本进入 Vue，并通过 `white-space: pre-wrap` 保留换行。不用它会怎样：一旦使用 `v-html`，恶意网页内容可能进入同源执行环境。
- **【所有权先于数据】**：读取链接标签时，先确认链接归当前用户，再读取关联标签。不用它会怎样：接口只按 `link_id` 查询，会让知道 id 的其他用户读到别人标签。
- **【信息层级来自问题】**：收藏页首先回答“我保存了什么、是否还能读”；详情页首先回答“这篇内容现在能否阅读”；证据栏回答“它留下了哪些副本”。不用它会怎样：页面会退化成 KPI、表格和按钮的平均组合，看不出产品重点。
- **【方向不是装饰】**：`Achromatic ledger` 把颜色留给数据与状态，用密度、对齐和版面区分区域。不用它会怎样：为了“高级感”加入渐变、发光和卡片阴影，最后变成常见 AI 后台模板。

## 3. 架构讲解（这一步在整体里占哪个位置）

- **分层位置**：浏览器 Vue 页面 → Axios → Spring MVC Controller → Service → MyBatis-Plus Mapper → MySQL；资产文件仍由现有 `AssetController` 授权读取。
- **页面路由**：
  - `/login`：登录与注册，不进入应用壳；
  - `/links`：收藏列表、保存入口、集合筛选；
  - `/links/:id`：元数据、正文阅读、标签、抓取进度和证据资产；
  - `/search`：全文搜索、集合/标签/日期筛选、游标翻页；
  - `/tags`：标签创建、改名、删除和真实使用次数。
- **目录数据流**：登录后加载 `GET /collections` + `GET /tags` → 写入 Pinia 目录 store → 收藏页、详情页和搜索页复用；标签增删改或链接所属集合变化后刷新相关目录。
- **详情数据流**：路由 id → 并行请求 `GET /links/{id}`、`GET /links/{id}/readable`、`GET /assets?linkId=...`、`GET /links/{id}/tags`、`GET /collections`、`GET /tags` → 链接与标签正常展示；正文 404 单独显示“正文尚未生成”；资产为空单独显示“尚未生成”。
- **保存数据流**：保存抽屉提交 `POST /links` → 响应 `{link, job}` → 跳转 `/links/{link.id}?job={job.id}` → 每 3 秒轮询 `GET /jobs/{job.id}` → 终态后刷新资产和正文，URL 中移除临时 `job` 参数。
- **搜索数据流**：查询条件 → `GET /search` → 使用 `data.items`、`data.nextCursor`、`data.hasMore` → 结果点击进入站内 `/links/:id`；“加载更多”只追加下一页，不重复第一页。
- **新增后端边界**：`GET /api/v1/links/{id}/tags` 返回 `ApiResponse<List<TagSummary>>`。链接不存在或不属于当前用户返回 `404 NOT_FOUND`；匿名请求返回 `401 AUTH_REQUIRED`；无标签返回 `200` 与空数组；标签按 id 升序。
- **改动边界**：新增 M7 前端样式、组件、页面、目录 store、Playwright 测试和上述只读接口；不修改已有 Flyway 迁移、表结构、任务状态机、资产格式或 M6 检索语义。
- **为什么放这层**：页面只负责展示与组合请求；所有权、排序和标签统计留在后端。若前端先拉全站标签再猜当前关联，会把授权规则泄漏成客户端逻辑。

## 5. 重难语法讲解

- **【Vue Router 动态参数】**：标准写法是 `route.params.id` 与 `watch(() => route.params.id, load, { immediate: true })`；`immediate` 表示首次进入就加载，`watch` 负责同一组件内从一篇详情跳到另一篇。常见错法：只在 `onMounted` 加载，第二次进入 `/links/2` 时仍显示 `/links/1` 的内容。
- **【纯文本保留换行】**：标准写法是 `<p class="readable-text">{{ textContent }}</p>`，CSS 使用 `white-space: pre-wrap`；`{{ }}` 会转义 HTML，`pre-wrap` 只保留空白和换行。常见错法：使用 `v-html` 追求段落样式，把不可信网页内容带入应用执行环境。
- **【游标分页】**：标准写法是首次请求不带 `cursor`，后续把上一页 `nextCursor` 原样传回，并只在 `hasMore` 为真时显示“加载更多”；不能解码或重写游标。常见错法：把它当页码自行加一，后端会因游标指纹不匹配返回 `400`。
- **【轮询生命周期】**：标准写法是在进入带 `job` 的详情页时启动定时器，在终态、路由变化和 `onBeforeUnmount` 时清理。常见错法：每次轮询成功都新建一个 `setInterval`，离开页面后仍继续请求。
- **【Pinia 派生数据】**：标准写法是把原始 `collections`、`tags` 放在 store，页面用 computed 计算筛选结果和选中项；不要让每个页面各存一份可编辑副本。常见错法：标签改名后详情页仍显示旧名称。
- **【组件动效降级】**：标准写法是 `prefers-reduced-motion: reduce` 下直接渲染最终数字并禁用位移/滚动。常见错法：只把动画时长设为 0，却仍改变布局，导致阅读位置跳动。

## 6. 具体实现

> 项目覆盖规则：本节不代替用户写后端生产实现。后端只给类/方法签名、契约、关键规则和验证方式；前端与测试可按确认后的范围由 Codex 实现。

### 新增后端标签读取契约

##### `backend/src/main/java/com/webcollector/link/controller/LinkController.java`

- **作用**：在现有 `/api/v1/links` 边界下公开当前链接的标签集合。
- **方法签名**：

```java
@GetMapping("/{id}/tags")
public ApiResponse<List<TagSummary>> listLinkTags(@PathVariable Long id)
```

- **关键规则**：
  - Controller 只接收 id，调用 `LinkService`，不自行查库。
  - 返回 `ApiResponse.success(...)`，不返回 `LinkTag` 实体。
  - 不改变现有 `GET /links/{id}`、`PUT /links/{id}/tags` 或 `LinkSummary`。

##### `backend/src/main/java/com/webcollector/link/service/LinkService.java`

- **作用**：先证明链接归当前用户，再返回该链接的标签摘要。
- **方法签名**：

```java
@Transactional(readOnly = true)
public List<TagSummary> listLinkTags(Long linkId)
```

- **关键伪代码**：

```text
userId = currentUserId()
requireOwnedLink(linkId, userId)
tagIds = link_tag 中 linkId 对应的 tag_id，去重并升序
若 tagIds 为空，返回空列表
只加载 userId 所有且 id 位于 tagIds 中的 Tag
复用现有标签计数语义构造 TagSummary
按 tagIds 顺序返回
```

- **关键 3 行**：
  - `requireOwnedLink(linkId, userId)`：所有权必须先于标签查询。
  - `@Transactional(readOnly = true)`：明确这是只读查询。
  - 最终按 `tag_id` 升序返回：契约稳定，前端无需排序。
- **怎么验证**：`mvn -pl backend -Dtest=LinkTagQueryServiceTest,LinkTagQueryControllerTest,LinkTagQueryIntegrationTest test`。

### Vue Bits 动效适配

##### `frontend/src/components/ArchiveCounter.vue`

- **作用**：把 Vue Bits `Counter` 改成只响应数字变化的轻量计数组件。
- **来源与许可**：MIT + Commons Clause；在 `frontend/THIRD_PARTY_NOTICES.md` 记录来源、作者和许可证。
- **改造要求**：
  - 保留数字滚轮和 `motion-v` 依赖；
  - 删除原组件的渐变遮罩，改用纯色裁切或直接隐藏遮罩；
  - 首次加载直接显示最终值，只在保存成功、标签增删后数字变化时播放；
  - `prefers-reduced-motion: reduce` 下直接显示静态数字。
- **怎么验证**：开启 reduced-motion 后无数字滚动；创建链接后收藏总数更新一次。

### 搜索与标签

##### `frontend/src/views/SearchView.vue`

- **作用**：消费 M6.2 的 `SearchPage`，支持条件与游标加载更多。
- **关键签名**：

```text
runSearch(reset = true)
  query: q, collectionId, tagIds, from, to, limit
  reset=true 时清空 items 与 cursor
  成功后追加 data.items，保存 data.nextCursor 与 data.hasMore
```

- **关键 3 行**：结果链接指向 `/links/{id}`；条件变化时重置游标；加载更多失败保留已有结果。
- **怎么验证**：搜索 `Example Domain` 能进入详情，而不是跳回原网页。

##### `frontend/src/views/TagsView.vue`

- **作用**：完成标签 CRUD 与真实使用次数展示。
- **操作契约**：
  - 新建：`POST /tags`，请求 `{name}`；
  - 改名：`PATCH /tags/{id}`，请求 `{name}`；
  - 删除：确认后 `DELETE /tags/{id}`，提示“只解除标签关联，不删除收藏”。
- **关键 3 行**：空名称不可提交；正在请求的行禁用重复操作；删除后刷新目录和当前筛选。
- **怎么验证**：创建标签、分配给链接、改名、删除后，收藏仍存在且标签关系消失。

### 浏览器 E2E

## 8. 坑（会怎么错，不是要注意什么）

- ❌ 用 `v-html="textContent"` 给正文加样式 → 抓取网页中的 HTML 进入应用同源上下文 → 改用 `{{ textContent }}` 与 `white-space: pre-wrap`。
- ❌ 在列表里逐条请求 `/links/{id}/tags` → 打开 100 条收藏产生上百个请求 → 列表不展示标签，只在详情页读取。
- ❌ 只按 `link_id` 查询标签 → 其他用户可读取不属于自己的标签 → 先按 `id + user_id` 验证链接所有权。
- ❌ 把 `SearchPage` 当数组渲染 → `v-for` 没有数据或分页游标完全失效 → 读取 `items`，保存 `nextCursor` 和 `hasMore`。
- ❌ 直接把 HTML 资产放进 iframe 或新同源窗口 → 不可信脚本可能在应用上下文运行 → HTML 资产只下载，不内联展示。
- ❌ 每次轮询后重新创建定时器 → 请求频率持续加倍，离开页面仍请求 → 只保留一个定时器并在终态/卸载时清理。
- ❌ 把 Element Plus 默认主色和圆角留在页面 → 新视觉仍像库默认模板 → 用全局 tokens 覆盖颜色、圆角、边框和焦点样式。
- ❌ 用 Noto 衬线渲染所有按钮和导航 → 阅读气质变成装饰，操作区辨识度下降 → 衬线只用于正文内容。
- ❌ 为了“有内容”给空账号塞假统计 → 用户看到的数字与实际收藏不一致 → 显示真实零值和下一步动作。

## A.1 方向选择

### 已选：证据档案

- 采用 `Achromatic ledger` 的开放式浅色工作台、无彩色导航和有限数据色。

- 字体从方向表的 Geist 改为 Noto Sans SC + Noto Serif SC，原因是产品主要使用中文且必须支持自托管离线运行。
