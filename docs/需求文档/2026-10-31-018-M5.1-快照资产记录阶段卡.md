# 二级阶段 M5.1：让每份快照都有落盘记录

**一句话**：把一次抓取生成的 HTML、PDF、截图登记为可追踪的 asset 记录，记录文件位置和内容校验信息。
**完成标志**：真实 MySQL 中能查到与链接及抓取任务关联的资产行；每个已登记文件可由路径读到，MIME、字节数和 SHA-256 与文件内容一致。
**实施状态**：阶段卡待确认；以下生产代码为用户明确要求提供的可抄参考实现，尚未写入源码或运行验证。
**预计时长**：2-3 小时　**依赖**：M4.1-M4.4 已完成；M4.5 进行中

---

#### 1. 涉及技术栈（为什么是它）
| 技术/组件 | 用在哪 | 为什么选它 | 备选 & 不选的理由 |
|---|---|---|---|
| Flyway + MySQL | 新增 `asset` 表 | 版本化演进且可用真实 MySQL 验证约束 | 不修改旧迁移，避免已部署库校验失败 |
| Java NIO `Path` / `Files` | 检查已有快照文件、取大小和 SHA-256 | 标准库能流式读取，避免整份 PDF 载入内存 | `File` API 较旧；暂不引入对象存储 SDK |
| `MessageDigest` | 内容 SHA-256 | 标准 JDK 算法，可用于完整性核验 | 不用 MD5/SHA-1，抗碰撞性不足 |

#### 2. 原理讲解（不用它会怎样）
- **元数据与文件分离**：数据库保存定位和校验信息，文件仍在本地磁盘。不登记时，重启后无法从 link/job 反查快照，也难以判断文件是否损坏。
- **摘要按字节计算**：SHA-256 对文件原始字节计算，而不是对文件名或解码后的文本计算。否则同名不同内容可能被误认为一致。
- **失败边界**：本步只在文件已生成后登记；文件系统和 MySQL 没有共同事务。登记失败可能留下孤儿文件，清理与原子写入归 M5.2，不承诺跨系统原子性。

#### 3. 架构讲解（这一步在整体里占哪个位置）
- **分层位置**：`CaptureJob/抓取结果 → AssetRegistrationService → AssetMapper → MySQL`，文件内容由 Java NIO 读取。
- **数据流向**：抓取结果中的 HTML/PDF/截图路径 → 校验普通文件 → MIME/大小/SHA-256 → 插入 `asset` → 返回登记结果。
- **改动边界**：新增 V10 迁移、Asset entity/mapper/service/DTO 及测试；不改历史迁移，不做授权读取、原子写、文件清理、Worker 调度或 HTTP 下载 API。
- **本卡契约假设**：首批登记 M4.2 `BrowserCaptureArtifacts` 的 HTML、PDF、PNG 三种产物；字段按 `id, link_id, capture_job_id, format, storage_path, mime_type, file_size_bytes, sha256, created_at`。同一 job + format 唯一；文件路径保存为相对配置根目录的规范化相对路径，绝不保存客户端可控路径。正文抽取产物暂不登记。若项目既有需求文档已另定格式或目录规则，以既有决策为准。

#### 4. 步骤（每步都能看到结果）
| # | 做什么 | 完成后能观察到什么 |
|---|---|---|
| 1 | 新增 V10 asset 表及约束 | Flyway 在干净 MySQL 完成迁移 |
| 2 | 新增 Asset 映射实体与 Mapper | 可插入并读回记录 |
| 3 | 实现登记服务：校验文件、计算 MIME/大小/SHA-256、保存相对路径 | 对测试文件登记后元数据与真实字节一致 |
| 4 | 单测 + Testcontainers 集成测试 | 缺文件/非法目录不落库；有效文件能落库并读回 |

#### 5. 重难语法讲解
- **`Files.newInputStream` + `MessageDigest`**：按缓冲区分块更新摘要，适合大文件；不要 `readAllBytes()`，否则大 PDF 会一次占满堆内存。
- **`Path.normalize()` / `startsWith(root)`**：把路径收敛到配置根目录并验证归属；不能用字符串 `startsWith`，例如 `/data/assets-evil` 会通过 `/data/assets` 的文本前缀判断。

#### 6. 具体实现

以下代码按项目现有 MyBatis-Plus、Flyway 与 Java 17 写法组织。`storage.root` 由部署配置提供（例如 `./data/assets`）；路径规范化必须同时验证真实路径位于真实根目录内。M5.1 只登记已经存在的文件，不负责创建快照文件。

CREATE TABLE asset
(
    id              BIGINT         NOT NULL AUTO_INCREMENT,
    link_id         BIGINT         NOT NULL,
    capture_job_id  BIGINT         NOT NULL,
    format          VARCHAR(16)    NOT NULL,
    storage_path    VARCHAR(1024)  NOT NULL,
    mime_type       VARCHAR(127)   NOT NULL,
    file_size_bytes BIGINT UNSIGNED NOT NULL,
    sha256          CHAR(64)       NOT NULL,
    created_at      DATETIME(3)    NOT NULL,
    PRIMARY KEY (id),
    CONSTRAINT ck_asset_format CHECK (format IN ('HTML', 'PDF', 'SCREENSHOT')),
    CONSTRAINT ck_asset_sha256 CHECK (sha256 REGEXP '^[0-9a-f]{64}$'),
    CONSTRAINT uk_asset_job_format UNIQUE (capture_job_id, format),
    KEY idx_asset_link_created (link_id, created_at DESC),
    CONSTRAINT fk_asset_link FOREIGN KEY (link_id) REFERENCES link (id) ON DELETE CASCADE,
    CONSTRAINT fk_asset_job FOREIGN KEY (capture_job_id) REFERENCES capture_job (id) ON DELETE CASCADE
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COLLATE = utf8mb4_0900_ai_ci
  COMMENT = '快照资产元数据';

##### `backend/src/main/java/com/webcollector/capture/asset/service/AssetRegistrationService.java`

```java
package com.webcollector.capture.asset.service;

import com.webcollector.capture.asset.entity.Asset;
import com.webcollector.capture.asset.entity.AssetFormat;
import com.webcollector.capture.asset.mapper.AssetMapper;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.io.IOException;
import java.io.InputStream;
import java.nio.file.Files;
import java.nio.file.LinkOption;
import java.nio.file.Path;
import java.security.MessageDigest;
import java.security.NoSuchAlgorithmException;
import java.time.Clock;
import java.time.LocalDateTime;
import java.util.HexFormat;

@Service
public class AssetRegistrationService {
    private final AssetMapper assetMapper;
    private final Path storageRoot;
    private final Clock clock;

    public AssetRegistrationService(
            AssetMapper assetMapper,
            @Value("${app.storage.root:./data/assets}") String storageRoot,
            Clock clock
    ) throws IOException {
        this.assetMapper = assetMapper;
        Path configuredRoot = Path.of(storageRoot).toAbsolutePath().normalize();
        Files.createDirectories(configuredRoot);
        this.storageRoot = configuredRoot.toRealPath();
        this.clock = clock;
    }

    /** 登记已生成的快照文件；同一任务同一格式只允许一条记录。 */
    @Transactional
    public Asset register(
            Long linkId,
            Long captureJobId,
            AssetFormat format,
            Path generatedFile
    ) {
        if (linkId == null || captureJobId == null || format == null || generatedFile == null) {
            throw new IllegalArgumentException("资产登记参数不能为空");
        }

        try {
            Path file = generatedFile.toAbsolutePath().normalize();
            if (!Files.isRegularFile(file, LinkOption.NOFOLLOW_LINKS)) {
                throw new IllegalArgumentException("快照路径不是普通文件");
            }
            Path realFile = file.toRealPath(LinkOption.NOFOLLOW_LINKS);
            if (!realFile.startsWith(storageRoot)) {
                throw new IllegalArgumentException("快照文件必须位于配置的存储根目录内");
            }

            Asset asset = new Asset();
            asset.setLinkId(linkId);
            asset.setCaptureJobId(captureJobId);
            asset.setFormat(format);
            asset.setStoragePath(storageRoot.relativize(realFile).toString().replace('\\', '/'));
            asset.setMimeType(resolveMimeType(format, realFile));
            asset.setFileSizeBytes(Files.size(realFile));
            asset.setSha256(sha256(realFile));
            asset.setCreatedAt(LocalDateTime.now(clock));
            assetMapper.insert(asset);
            return asset;
        } catch (IOException exception) {
            throw new IllegalStateException("读取快照文件元数据失败", exception);
        }
    }

    private String resolveMimeType(AssetFormat format, Path file) throws IOException {
        String detected = Files.probeContentType(file);
        String expected = switch (format) {
            case HTML -> "text/html";
            case PDF -> "application/pdf";
            case SCREENSHOT -> "image/png";
        };
        if (detected != null && !isCompatibleMime(expected, detected)) {
            throw new IllegalArgumentException("文件 MIME 与资产格式不匹配: " + detected);
        }
        return expected;
    }

    private boolean isCompatibleMime(String expected, String detected) {
        return expected.equalsIgnoreCase(detected)
                || (expected.equals("text/html") && detected.equalsIgnoreCase("text/plain"));
    }

    private String sha256(Path file) throws IOException {
        try {
            MessageDigest digest = MessageDigest.getInstance("SHA-256");
            byte[] buffer = new byte[8192];
            try (InputStream input = Files.newInputStream(file)) {
                int count;
                while ((count = input.read(buffer)) != -1) {
                    digest.update(buffer, 0, count);
                }
            }
            return HexFormat.of().formatHex(digest.digest());
        } catch (NoSuchAlgorithmException exception) {
            throw new IllegalStateException("当前 JRE 不支持 SHA-256", exception);
        }
    }
}
```

**关键约束**：必须把输出目录配置在 `app.storage.root` 下；先校验真实路径归属，再存相对路径。SHA-256 分块读取。`link_id` 与 `capture_job_id` 的对应关系需要由调用方从已认领 job 得出，数据库外键分别保证存在，但不保证二者属于同一条 link；集成测试应覆盖这一不变量，若需数据库级保证可在本阶段调整为复合外键。

**怎么验证**：测试文件放在临时 storage root；对登记结果断言 `file_size_bytes == Files.size(file)`、`sha256 ==` 独立计算结果，随后 `AssetMapper.selectById` 读回；越界路径、缺失文件和非普通文件拒绝且不插入；运行 `mvn -pl backend test`。

#### 7. 计算机四大件映射
- **映射到**：操作系统、数据结构与算法。
- **具体机制**：文件流分块读取降低峰值内存；SHA-256 顺序处理字节流，时间复杂度 O(n)，额外空间 O(1)。
- **在哪一段代码体现**：`sha256` 方法中的 8192 字节 buffer 与 `MessageDigest.update`。

#### 8. 坑（会怎么错，不是要注意什么）
- ❌ 直接保存绝对路径 → 换机器或配置根目录后失效并暴露本机目录 → 保存根目录内的规范化相对路径。
- ❌ `Files.readAllBytes` 后算摘要 → 大 PDF 导致堆内存暴涨 → 固定缓冲区流式计算。
- ❌ 只检查 `normalize()` 后的字符串前缀 → 符号链接或相似目录可越界 → 使用真实路径并以 `Path.startsWith` 判断。
- ❌ 把数据库事务当作文件系统事务 → DB 回滚但文件仍存在 → 接受 M5.1 的孤儿文件边界，在 M5.2 实现清理/原子写入。
