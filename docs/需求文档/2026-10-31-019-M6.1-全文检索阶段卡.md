# 二级阶段 M6.1：让中英文内容都能被搜到

**一句话**：新增一个按当前登录用户隔离的全文搜索接口，用 MySQL ngram 全文索引匹配链接标题、描述和已采集正文。
**完成标志**：MySQL 8.4 上中英文样例均能命中；不同用户的数据不串；空白 query 返回 400；合法无匹配词返回空数组。
**实施状态（2026-11-02）**：V14、Mapper、Service、Controller 与真实 MySQL 集成测试已完成；工程与自动化验收通过。
**数据边界**：新保存链接经真实 Worker 自动写入正文；历史链接暂无正文回填来源，需要重新采集后才能搜索到正文。
**预计时长**：2-3 小时　**依赖**：M4 正文自动持久化链路已接入生产 Worker；V10-V14 迁移已在 MySQL 8.4 验证。

#### 1. 涉及技术栈（为什么是它）
| 技术/组件 | 用在哪 | 为什么选它 | 备选 & 不选的理由 |
|---|---|---|---|
| MySQL 8.4 FULLTEXT + ngram | 标题、描述、正文索引 | 已是项目选型，不增加搜索服务和数据同步链路 | Elasticsearch/Meilisearch 增加部署与一致性成本，留待规模需要时评估 |
| MyBatis `@Select` + `@Param` | `MATCH ... AGAINST` 参数化查询 | 保留 MATCH 语法并使用绑定参数，当前 Mapper 风格已使用注解 SQL | QueryWrapper 不适合清晰表达 MySQL 全文函数 |
| Spring Web + Sa-Token session service | `GET /api/v1/search` | 复用统一响应与当前用户解析 | 不从 query 接受 userId，避免越权查询 |

#### 2. 原理讲解（不用它会怎样）
- **FULLTEXT 倒排索引**：按词项定位候选行，而不是逐行 `LIKE '%词%'`；不用它，数据增加后每次检索都可能扫描整张 link 表。
- **ngram 分词**：把连续文本拆成固定长度片段，适配中日韩文本；不用 ngram，MySQL 默认分词对中文通常无法按预期检索。短于 `ngram_token_size` 的词项可能无法命中，必须在真实 MySQL 8.4 验收并记录运行配置，不能宣称任意单字搜索都有效。
- **用户范围约束**：全文索引只负责文本匹配，不负责授权；若 SQL 漏掉 `user_id = 当前用户`，搜索会泄露其他账号的收藏。

#### 3. 架构讲解（这一步在整体里占哪个位置）
- **分层位置**：`GET /api/v1/search → SearchController → LinkSearchService → LinkMapper → MySQL`。
- **数据流向**：校验 `q` → 从 `SessionTokenService` 取登录用户 → 参数化 MATCH 查询 → 映射现有 `LinkSummary` → `ApiResponse`。
- **改动边界**：新增全文索引 Flyway 迁移、LinkMapper 搜索方法、新 SearchService/Controller；补搜索集成测试和接口/数据库文档。不改历史迁移、不改 Link 实体、不改已有 Link 接口。正文列及持久化服务由 M4 提供，但需先由 Worker 实际调用。
- **版本前置**：V10 创建 asset，V11 增加 asset 唯一约束，V12 创建 asset 清理队列，V13 增加 link.text_content，V14 启用全文索引。不得复用或修改已执行版本。
- **为什么放这层**：Controller 只做 HTTP 参数/响应，Service 解析当前用户，Mapper 写数据库专属全文 SQL；若把授权写在 Controller 或只依赖全文索引，其他调用路径容易漏隔离。
- **本卡 API 建议**：`GET /api/v1/search?q=...` 返回 `ApiResponse<List<LinkSummary>>`。当前接口文档列出的标签/集合/时间过滤、游标、资产元数据不纳入 M6.1；过滤与分页归 M6.2，资产返回契约按 M5 完成情况另定。

#### 5. 重难语法讲解
- **`MATCH(title, description, text_content) AGAINST (#{query} IN NATURAL LANGUAGE MODE)`**：列集合必须与 FULLTEXT 索引列一致；`#{query}` 是 JDBC 绑定参数，不要改成 `${query}`，后者会把输入拼进 SQL。
- **`WITH PARSER ngram`**：只在创建 FULLTEXT 索引时指定 parser；不要把它写到 MATCH 表达式里。ngram 长度由 MySQL 实例配置控制，变更全局设置不是本阶段默认动作。

#### 6. 具体实现

##### `backend/src/main/resources/db/migration-drafts/V14__add_link_fulltext_index.sql`
- **作用**：M6.1 开始时，在 M4 Worker 接线已将正文写入 `text_content` 后，为三种可搜索文本字段新增 ngram 全文索引。当前文件不在 Flyway 活跃迁移路径中。
- **前置检查**：若 `text_content` 尚不存在，不要执行本迁移；先完成 M4 的字段迁移和抓取正文持久化，并确认现有数据如何回填。仅新增空列无法满足“正文可搜”的完成标志。
- **完整代码**：

```sql
ALTER TABLE link
    ADD FULLTEXT INDEX ft_link_content (title, description, text_content)
    WITH PARSER ngram;
```

##### `backend/src/main/java/com/webcollector/link/mapper/LinkMapper.java`
- **作用**：通过 MySQL FULLTEXT 查询当前用户拥有且命中的链接。
- **完整代码**：在现有 imports 与接口内加入以下 import/方法，保留既有注释和 `extends BaseMapper<Link>`：

```java
import org.apache.ibatis.annotations.Param;
import org.apache.ibatis.annotations.Select;

import java.util.List;

@Select("""
        SELECT id, user_id, collection_id, original_url, normalized_url,
               url_hash, title, description, created_at, updated_at
        FROM link
        WHERE user_id = #{userId}
          AND MATCH(title, description, text_content)
              AGAINST (#{query} IN NATURAL LANGUAGE MODE)
        ORDER BY id DESC
        """)
List<Link> searchOwnedLinks(
        @Param("userId") Long userId,
        @Param("query") String query
);
```

##### `backend/src/main/java/com/webcollector/search/service/LinkSearchService.java`
- **作用**：规范化输入、获取当前用户、调用全文查询並映射安全摘要。
- **完整代码**：

```java
package com.webcollector.search.service;

import com.webcollector.auth.session.SessionTokenService;
import com.webcollector.link.dto.LinkSummary;
import com.webcollector.link.entity.Link;
import com.webcollector.link.mapper.LinkMapper;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.time.ZoneOffset;
import java.util.List;

@Service
public class LinkSearchService {
    private final LinkMapper linkMapper;
    private final SessionTokenService sessionTokenService;

    public LinkSearchService(
            LinkMapper linkMapper,
            SessionTokenService sessionTokenService
    ) {
        this.linkMapper = linkMapper;
        this.sessionTokenService = sessionTokenService;
    }

    @Transactional(readOnly = true)
    public List<LinkSummary> search(String query) {
        String normalizedQuery = query.trim();
        Long userId = sessionTokenService.requireLoginId();

        return linkMapper.searchOwnedLinks(userId, normalizedQuery)
                .stream()
                .map(this::toSummary)
                .toList();
    }

    private LinkSummary toSummary(Link link) {
        return new LinkSummary(
                link.getId(),
                link.getCollectionId(),
                link.getOriginalUrl(),
                link.getTitle(),
                link.getDescription(),
                link.getCreatedAt().toInstant(ZoneOffset.UTC),
                link.getUpdatedAt().toInstant(ZoneOffset.UTC)
        );
    }
}
```

##### `backend/src/main/java/com/webcollector/search/controller/SearchController.java`
- **作用**：暴露校验后的 GET 搜索端点，使用项目统一响应封装。
- **完整代码**：

```java
package com.webcollector.search.controller;

import com.webcollector.common.web.ApiResponse;
import com.webcollector.link.dto.LinkSummary;
import com.webcollector.search.service.LinkSearchService;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Size;
import org.springframework.validation.annotation.Validated;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

import java.util.List;

@Validated
@RestController
@RequestMapping("/api/v1/search")
public class SearchController {
    private final LinkSearchService linkSearchService;

    public SearchController(LinkSearchService linkSearchService) {
        this.linkSearchService = linkSearchService;
    }

    @GetMapping
    public ApiResponse<List<LinkSummary>> search(
            @RequestParam("q")
            @NotBlank(message = "搜索词不能为空")
            @Size(max = 200, message = "搜索词不能超过 200 个字符")
            String query
    ) {
        return ApiResponse.success(linkSearchService.search(query));
    }
}
```

**关键约束**：全文 MATCH 列必须与索引一致；SQL 始终绑定 `userId` 和 `query`；不能返回 Link 实体或正文；GET 查询只接受当前会话身份。响应排序当前按 `id DESC`，M6.2 若定义相关度排序需单独调整接口契约。

**怎么验证**：执行 `mvn -pl backend test`。`SearchIntegrationTest` 已验证中英文标题/正文、零结果、跨用户隔离、空白/超长参数、未登录和 `EXPLAIN` 使用 `ft_link_content`；全量 324 项通过、4 跳过。

#### 7. 计算机四大件映射
- **映射到**：数据结构与算法。
- **具体机制**：FULLTEXT 倒排索引通过词项到文档集合的映射缩小候选集；索引更新会增加写入与存储成本。
- **在哪一行代码体现**：V14 迁移的 `ADD FULLTEXT INDEX` 与 Mapper 中的 `MATCH ... AGAINST`。

#### 8. 坑（会怎么错，不是要注意什么）
- ❌ 用 `LIKE '%query%'` 冒充全文检索 → 中文结果看似可用但大表扫描且不使用全文索引 → 使用 MATCH 并用 `EXPLAIN` 验证计划。
- ❌ MATCH 列与 FULLTEXT 索引列不一致 → MySQL 报 `FULLTEXT index does not match the column list` → 索引和 MATCH 固定使用 title、description、text_content 三列。
- ❌ 忘记 `user_id = #{userId}` → 命中其他用户的链接 → 用户 ID 只能由服务端会话解析并进入 SQL 条件。
- ❌ 把 `${query}` 拼入注解 SQL → 特殊输入改变 SQL 结构 → 只用 `#{query}` 绑定参数。
- ❌ 假设 ngram 一定能搜单个英文字符 → 结果可能为空 → 按部署实例的 `ngram_token_size` 明确产品边界并实测短词。
