### 二级阶段 M4.5：让抓取失败时坏得体面

**一句话**：网页快照的 HTML、PDF、截图分别尝试生成，单一格式失败不删除其他已成功文件。
**完成标志**：导航失败能整体报错；格式导出各自返回成功路径或失败原因；已成功文件在另一格式失败后仍保留。
**实施状态（2026-10-31）**：生产代码、M4.5 专项测试和全量回归已完成。
**预计时长**：一次实现会话　**依赖**：M4.4 工程与自动化验收已完成；其学习验收仍待用户回答

#### 1. 涉及技术栈（为什么是它）

| 技术/组件 | 用在哪 | 为什么选它 | 备选 & 不选的理由 |
|---|---|---|---|
| Playwright Java | 同一页面分别导出 HTML、PDF、截图 | 已有单次导航与三格式输出能力，只需隔离每种导出错误 | 每个格式重新导航会产生不同页面状态，也增加浏览器开销 |
| Java record | 表达每种格式的单项结果和总快照结果 | 成功路径与失败原因能按格式明确返回 | 继续使用三个必填 `Path` 会无法表达部分成功 |
| Java NIO 临时文件/移动 | 防止单个格式写到一半留下损坏文件 | 仅在单格式成功后发布最终文件 | 直接写最终路径时，失败可能留下貌似完整的残缺文件 |

#### 2. 原理讲解（不用它会怎样）

- **每格式隔离失败**：HTML、PDF、截图分别执行，单个格式异常记录在该格式结果中，不中断其他格式。不用它：PDF 失败会把已经成功生成的 HTML 和截图也删掉。
- **临时文件发布**：先写同目录临时文件，成功后移动为正式名称；失败只删除本格式临时文件。不用它：文件系统会残留截断文件，后续被误认为成功产物。
- **页面级与格式级错误分层**：URL 校验、导航、浏览器启动失败属于整次采集失败；导航成功后的单格式导出失败属于部分结果。不用它：调用方无法决定任务应重试还是保留部分快照。
- **可用快照判据**：沿用业务流程已有规则，HTML 或截图至少一种成功即可作为可用快照；只有 PDF 成功不满足该规则。不用它：调用方会对同一组格式结果作出不一致的任务结论。

#### 3. 架构讲解（这一步在整体里占哪个位置）

- **分层位置**：`Worker/采集服务 → PlaywrightBrowserHtmlCapture → PageArtifactExporter → 文件系统`。
- **数据流向**：

```text
校验 URL 并完成一次导航
  → 分别导出 HTML / PNG / PDF 到各自临时文件
  → 单项成功：发布该格式文件并记录路径
  → 单项失败：删除该格式临时文件并记录错误，继续其他格式
  → 返回三项结果与 hasUsableSnapshot
  → 导航/浏览器级失败：整体抛出异常
```

- **改动边界**：调整 `BrowserCaptureArtifacts` 结果契约和 `captureSnapshot` 的错误处理；新增格式结果类型及可注入导出器测试缝；不接 `CaptureJobService`、不新增 asset 表、HTTP API、重试策略或状态枚举。
- **为什么放这层**：格式导出错误属于捕获基础设施；任务是否完成、失败重试仍由 Worker/任务协调层决定。

#### 5. 重难语法讲解

- **sealed/record 结果契约**：建议用普通 record 表示 `ArtifactResult(Path path, String errorCode, String errorMessage)`，构造时校验“成功时有 path、失败时有错误”；避免用 `null` 暗示状态。
- **格式级异常捕获**：每种导出单独 `try/catch`，只捕获该格式的运行时/文件异常；不要用一个外层 catch 把三种导出重新变成全失败。
- **临时文件移动**：同目录临时文件成功后使用 `Files.move` 发布；不支持原子移动时回退到普通 move，但目标已存在时不得覆盖。

#### 6. 具体实现

##### `backend/src/main/java/com/webcollector/capture/browser/ArtifactResult.java`
- **作用**：表达一种格式的独立成功或失败。
```java
package com.webcollector.capture.browser;

import java.nio.file.Path;
import java.util.Objects;

public record ArtifactResult(Path path, String errorCode, String errorMessage) {
    public ArtifactResult {
        if (path == null && (errorCode == null || errorCode.isBlank())) {
            throw new IllegalArgumentException("失败结果必须包含错误码");
        }
        if (path != null && errorCode != null) {
            throw new IllegalArgumentException("成功结果不能包含错误码");
        }
    }
    public static ArtifactResult succeeded(Path path) {
        return new ArtifactResult(Objects.requireNonNull(path, "path"), null, null);
    }
    public static ArtifactResult failed(String code, String message) {
        return new ArtifactResult(null, Objects.requireNonNull(code, "errorCode"), message);
    }
    public boolean isSuccess() { return path != null; }
    public boolean succeeded() { return isSuccess(); }
}
```

##### `backend/src/main/java/com/webcollector/capture/browser/BrowserCaptureArtifacts.java`
- **作用**：承载 HTML、PDF、截图三项结果。
```java
package com.webcollector.capture.browser;

import java.nio.file.Path;

public record BrowserCaptureArtifacts(
        ArtifactResult html, ArtifactResult pdf, ArtifactResult screenshot) {
    public BrowserCaptureArtifacts {
        if (html == null || pdf == null || screenshot == null) {
            throw new IllegalArgumentException("三种格式结果不能为空");
        }
    }
    public boolean hasUsableSnapshot() {
        return html.isSuccess() || screenshot.isSuccess();
    }
    public Path htmlPath() { return html.path(); }
    public Path pdfPath() { return pdf.path(); }
    public Path screenshotPath() { return screenshot.path(); }
}
```

##### `backend/src/main/java/com/webcollector/capture/browser/PlaywrightBrowserHtmlCapture.java`
- **行为**：导航成功后尝试三种格式；每种格式写独立临时文件，成功后 move 到 `page.html`、`page.pdf`、`screenshot.png`。格式失败时清理本格式临时文件、记录稳定错误码/消息并继续。
- **整体失败**：URL 安全检查、重定向预检、浏览器启动或主页面导航失败时整体抛异常；不得返回伪造的三项格式失败结果。
- **覆盖保护**：最终目标任一已存在时，调用开始前拒绝执行，不覆盖旧快照。
```java
interface PageArtifactExporter {
    void writeHtml(Page page, Path target) throws Exception;
    void writePdf(Page page, Path target) throws Exception;
    void writeScreenshot(Page page, Path target) throws Exception;
}
```

核心实现为：导航成功后为三种格式分别调用 `exportOne`；该方法生成同目录随机临时文件，导出成功后 `ATOMIC_MOVE`（不支持时回退普通 `move`），失败只删除自己的临时文件并返回 `ARTIFACT_EXPORT_FAILED`。导航、浏览器启动和 URL 预检异常仍直接抛出，不伪装成格式失败。

其中两个导出器的完整实现如下：

```java
package com.webcollector.capture.browser;

import com.microsoft.playwright.Page;
import com.microsoft.playwright.options.ScreenshotType;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;

final class PlaywrightPageArtifactExporter implements PageArtifactExporter {
    public void writeHtml(Page page, Path target) throws Exception {
        Files.writeString(target, page.content(), StandardCharsets.UTF_8);
    }
    public void writePdf(Page page, Path target) {
        page.pdf(new Page.PdfOptions().setPath(target).setFormat("A4").setPrintBackground(true));
    }
    public void writeScreenshot(Page page, Path target) {
        page.screenshot(new Page.ScreenshotOptions().setPath(target)
                .setFullPage(true).setType(ScreenshotType.PNG));
    }
}
```

`PlaywrightBrowserHtmlCapture` 保留 M4.1 的 `capture`、M4.2 的 `captureSnapshot`、M4.4 的 URL 预检与子资源拦截；其 M4.5 关键实现如下：

```java
private ArtifactResult exportOne(Page page, Path target, String format,
                                 ExportAction action) {
    Path temporary = target.resolveSibling(
            target.getFileName() + ".tmp-" + System.nanoTime());
    try {
        action.write(page, temporary);
        moveWithoutOverwrite(temporary, target);
        return ArtifactResult.succeeded(target);
    } catch (Exception exception) {
        try {
            Files.deleteIfExists(temporary);
        } catch (IOException cleanupFailure) {
            exception.addSuppressed(cleanupFailure);
        }
        return ArtifactResult.failed(
                "ARTIFACT_EXPORT_FAILED",
                format + " 导出失败: " + stableMessage(exception));
    }
}

private void moveWithoutOverwrite(Path source, Path target) throws IOException {
    try {
        Files.move(source, target, StandardCopyOption.ATOMIC_MOVE);
    } catch (AtomicMoveNotSupportedException exception) {
        Files.move(source, target);
    }
}
```

`captureSnapshot` 在页面导航和 HTML 大小校验完成后执行：

#### 8. 坑（会怎么错，不是要注意什么）

- ❌ 任一格式失败就删除整个输出目录 → 已成功文件丢失 → 每种格式单独清理临时文件。
- ❌ 直接把导出写到最终路径 → 崩溃后留下损坏文件 → 临时写完后再 move 发布。
- ❌ 三个结果字段仍要求非空 Path → 部分失败无法表达 → 改为逐格式结果。
- ❌ 单一 PDF 成功就认为快照可用 → 不符合既有“至少 HTML 或截图”规则 → 统一由 `hasUsableSnapshot()` 判定。
- ❌ 格式失败直接调用 `CaptureJobService.fail` → 采集组件越权决定任务重试 → 本步只返回结果，不改任务状态。

**能讲（Codex 先示范，用户随后合上材料作答）**
- [ ] Q1：为什么每种格式要用自己的临时文件，而不是共用一个“快照成功/失败”标志？

  > **参考示范**：格式是独立产物，PDF 生成失败不应删除已经写好的 HTML；临时文件能让失败产物不以正式文件名出现，调用方也能逐项看到路径和错误。

  > **参考示范**：现有任务流程明确以 HTML 或截图至少一种成功作为可用快照条件；PDF 单独成功不满足该契约，所以结果对象必须把“有文件”和“有可用快照”区分开。
