### 二级阶段 M4.5：让抓取失败时坏得体面

**一句话**：HTML、PDF、截图不再被当成一个全有或全无的结果；某一种格式失败时，已经成功写入的文件继续保留，并返回每种格式的独立结果。页面导航或浏览器整体崩溃仍视为本次采集失败。
**完成标志**：同一次页面导航中，三种格式分别得到 `SUCCESS/FAILED` 结果；单格式失败不会删除其他成功文件；浏览器级失败不会伪造成功结果。
**实施状态（2026-11-02）**：工程实现与自动化验收完成；学习题待用户回答。
**预计时长**：2–4 小时　**依赖**：M4.1、M4.2、M4.3、M4.4

#### 1. 涉及技术栈（为什么是它）
| 技术/组件 | 用在哪 | 为什么选它 | 备选 & 不选的理由 |
|---|---|---|---|
| Java `record` | 表达单格式结果和组合结果 | 不可变、字段明确，适合一次捕获的返回值 | `Map` 类型不安全，调用方容易写错键 |
| Playwright Java | 页面导航、HTML/PDF/PNG 导出 | 复用 M4.1–M4.4 的安全导航和同一 `Page` | 不改为三次导航，避免重复访问和结果不一致 |
| `Files.deleteIfExists` | 仅清理当前格式的半成品 | 防止失败格式留下损坏文件 | 不清理其他格式，保留部分成功资产 |

#### 2. 原理讲解（不用它会怎样）
- **独立结果**：每个格式拥有自己的状态、路径和错误信息；否则调用方只能看到一个总异常，无法知道 HTML 是否已经可用。
- **失败隔离**：单格式导出包在自己的 `try/catch` 中；否则 PDF 失败会触发 M4.2 的总清理，把已经成功的 HTML 和 PNG 一并删掉。
- **失败分层**：导航失败是页面级失败，格式导出失败是格式级失败；混在一起会把浏览器崩溃误报成“只有 PDF 失败”。

#### 3. 架构讲解（这一步在整体里占哪个位置）
- **分层位置**：`PlaywrightBrowserHtmlCapture`（capture adapter），暂不接 Controller、Job、Mapper 或数据库。
- **数据流向**：校验 URL → 安全逐跳导航 → 读取 DOM → 分别尝试 HTML/PDF/PNG → 返回逐格式结果。
- **改动边界**：修改 `BrowserCaptureArtifacts`、`BrowserHtmlCapture`、`PlaywrightBrowserHtmlCapture`；新增/修改浏览器捕获测试。不新增表、迁移、HTTP 接口、Worker 状态。
- **为什么放这层**：失败原因只在导出适配器最清楚；上层只消费稳定结果，不能依赖 Playwright 异常类型。

#### 4. 步骤（每步都能看到结果）
| # | 做什么 | 完成后能观察到什么 |
|---|---|---|
| 1 | 把三件套结果改为逐格式结果 | 编译器要求调用方读取 `html/pdf/screenshot` 三个字段 |

#### 5. 重难语法讲解
- **结果 record**：`new CaptureFormatResult(CaptureFormat.HTML, SUCCESS, path, null)`；字段不可变，禁止用可变实体承载一次性结果。
- **异常隔离**：`try { write } catch (Exception e) { delete(path); return failed(e); }`；只删除当前格式路径，不能调用旧的全量清理。

```java
package com.webcollector.capture.browser;

import java.nio.file.Path;

public record CaptureFormatResult(
        CaptureFormat format,
        CaptureFormatStatus status,
        Path path,
        String errorMessage
) {
    public static CaptureFormatResult success(CaptureFormat format, Path path) {
        return new CaptureFormatResult(format, CaptureFormatStatus.SUCCESS, path, null);
    }

    public static CaptureFormatResult failed(CaptureFormat format, String message) {
        return new CaptureFormatResult(format, CaptureFormatStatus.FAILED, null, message);
    }
}
```

##### `backend/src/main/java/com/webcollector/capture/browser/BrowserCaptureArtifacts.java`
```java
package com.webcollector.capture.browser;

import java.nio.file.Path;

public record BrowserCaptureArtifacts(
        CaptureFormatResult html,
        CaptureFormatResult pdf,
        CaptureFormatResult screenshot
) {
    public boolean hasAnySuccess() {
        return html.status() == CaptureFormatStatus.SUCCESS
                || pdf.status() == CaptureFormatStatus.SUCCESS
                || screenshot.status() == CaptureFormatStatus.SUCCESS;
    }
}
```

##### `backend/src/main/java/com/webcollector/capture/browser/PlaywrightBrowserHtmlCapture.java`
将现有 `captureSnapshot` 替换为以下实现，并新增两个辅助方法：
```java
@Override
public BrowserCaptureArtifacts captureSnapshot(String url, Path outputDirectory) {
    validateBasicUrl(url);
    if (outputDirectory == null) {
        throw new IllegalArgumentException("outputDirectory 不能为空");
    }
    URI safeUrl = safeNavigationClient.validateRedirectChain(url);
    Path directory = outputDirectory.toAbsolutePath().normalize();
    Path html = directory.resolve("page.html");
    Path pdf = directory.resolve("page.pdf");
    Path screenshot = directory.resolve("screenshot.png");
    for (Path path : List.of(html, pdf, screenshot)) {
        if (Files.exists(path)) {
            throw new IllegalStateException("快照文件已存在，拒绝覆盖: " + path);
        }
    }

    try (Playwright playwright = Playwright.create();
         Browser browser = playwright.chromium().launch(
                 new BrowserType.LaunchOptions().setHeadless(true));
         BrowserContext context = browser.newContext(
                 new Browser.NewContextOptions().setViewportSize(1280, 720));
         Page page = context.newPage()) {
        context.setDefaultTimeout(NAVIGATION_TIMEOUT_MILLIS);
        page.route("**/*", this::handleSubresource);
        page.navigate(safeUrl.toString());
        String renderedHtml = page.content();
        ensureHtmlSize(renderedHtml);
        Files.createDirectories(directory);

        CaptureFormatResult htmlResult = writeHtml(html, renderedHtml);
        CaptureFormatResult screenshotResult = writeScreenshot(page, screenshot);
        CaptureFormatResult pdfResult = writePdf(page, pdf);
        return new BrowserCaptureArtifacts(htmlResult, pdfResult, screenshotResult);
    } catch (NavigationLimitException exception) {
        throw exception;
    } catch (Exception exception) {
        throw new IllegalStateException("安全网页导航失败: " + url, exception);
    }
}

private CaptureFormatResult writeHtml(Path path, String html) {
    try {
        Files.writeString(path, html, StandardCharsets.UTF_8);
        return CaptureFormatResult.success(CaptureFormat.HTML, path);
    } catch (Exception exception) {
        deleteQuietly(path, exception);
        return CaptureFormatResult.failed(CaptureFormat.HTML, messageOf(exception));
    }
}

private CaptureFormatResult writeScreenshot(Page page, Path path) {
    try {
        page.screenshot(new Page.ScreenshotOptions().setPath(path)
                .setFullPage(true).setType(ScreenshotType.PNG));
        return CaptureFormatResult.success(CaptureFormat.SCREENSHOT, path);
    } catch (Exception exception) {
        deleteQuietly(path, exception);
        return CaptureFormatResult.failed(CaptureFormat.SCREENSHOT, messageOf(exception));
    }
}

private CaptureFormatResult writePdf(Page page, Path path) {
    try {
        page.pdf(new Page.PdfOptions().setPath(path)
                .setFormat("A4").setPrintBackground(true));
        return CaptureFormatResult.success(CaptureFormat.PDF, path);
    } catch (Exception exception) {
        deleteQuietly(path, exception);
        return CaptureFormatResult.failed(CaptureFormat.PDF, messageOf(exception));
    }
}

private void deleteQuietly(Path path, Exception original) {
    try {
        Files.deleteIfExists(path);
    } catch (IOException cleanupFailure) {
        original.addSuppressed(cleanupFailure);
    }
}

private String messageOf(Exception exception) {
    return exception.getMessage() == null
            ? exception.getClass().getSimpleName()
            : exception.getMessage();
}
```

**关键 3 行**：`page.navigate(...)` 是页面级边界；三个 `writeXxx` 必须互相独立；`deleteQuietly(path, ...)` 只能接收当前格式路径。

**兼容性说明**：旧测试不能再断言 `artifacts.htmlPath()`；统一改为 `artifacts.html().path()`，并新增 `status()` 断言。

#### 7. 计算机四大件映射
- **映射到**：计算机网络。
- **具体机制**：导航阶段的连接/响应失败与导出阶段的本地文件写入失败属于不同故障域；代码通过页面级与格式级异常边界分别处理。
- **在哪一行代码体现**：`page.navigate(...)` 外层 `try` 与三个 `writeXxx` 内层 `try/catch`。

#### 8. 坑（会怎么错，不是要注意什么）
- ❌ 在总 `catch` 中删除三个文件 → PDF 失败时 HTML/PNG 丢失 → 只删除当前格式半成品。
- ❌ 把格式失败重新抛出 → 调用方拿不到部分成功结果 → 返回 `FAILED` 结果对象。
- ❌ 页面导航失败也返回三个 `FAILED` → 把“未开始导出”和“导出失败”混为一谈 → 页面级失败继续抛异常。
- ❌ 为了测试强行改生产类增加注入开关 → 生产代码出现测试后门 → 用 Playwright 可控的 `Page` 行为或独立测试夹具验证。

**能讲（先看参考，再合上材料复述）**
- [ ] Q1：为什么 M4.5 要把“页面级失败”和“格式级失败”分开？
  > 参考示范：页面没导航成功就没有可靠 DOM，属于整次采集失败；HTML、PDF、PNG 是同一 DOM 的不同导出动作，某个动作失败不应抹掉已成功的资产，所以分别建结果和清理边界。
- [ ] Q2：如果 PDF 导出耗时或失败，为什么不重新导航一次再导出？
  > 参考示范：重新导航会重复请求页面、可能得到不同动态状态，也会放大 SSRF、超时和资源消耗；M4.5 先复用同一 `Page`，把故障隔离在单格式导出。
