#### 1. 涉及技术栈（为什么是它）

| 技术/组件 | 用在哪 | 为什么选它 | 备选 & 不选的理由 |
|---|---|---|---|
| Spring MVC | `GET /api/v1/links/{id}/readable` | 沿用现有接口与统一响应 | 不另建文件下载 Controller，避免重复鉴权 |
| MyBatis-Plus | 按 link、用户和类型定位资产 | 把用户范围过滤放进 SQL | 不先按资产 ID 查再校验，减少越权风险 |
| Java NIO `Path` | 解析存储根目录下的相对路径 | 可规范化并校验路径仍在根目录内 | 不用字符串前缀判断，防止相似目录绕过 |
| Spring `Resource` + UTF-8 | 有界读取并返回清洗 HTML | 标准 HTTP 资源抽象；限制读取字符数 | 不用 `Files.readString` 无上限加载大文件 |

#### 2. 原理讲解（不用它会怎样）

- **对象级授权**：查链接时同时带 `id + user_id`。不用它：知道他人链接 ID 就可能读到私人快照。
- **路径边界**：只接受数据库中的根目录相对路径，并校验规范化路径仍位于根目录内。不用它：被污染的 `../` 可读取服务器其他文件。
- **HTML 安全边界**：只回传 M4.3 生成的清理 HTML，接口声明 `text/html` 且禁止浏览器嗅探。不用它：原始页面中的脚本可能在产品域名下执行。
- **有界读取**：流式读取并限制最大字节数。不用它：异常大文件可耗尽 API 实例堆内存。

#### 3. 架构讲解（这一步在整体里占哪个位置）

- **分层位置**：Controller → `ReadableContentService` → Link/Asset Mapper + 本地文件系统。
- **数据流向**：认证用户 → `link.id + link.user_id` 校验 → 查该链接最新 `READABLE` asset → 根目录内解析相对路径 → 有界读取 UTF-8 清理 HTML → 返回 HTML 响应。
- **改动边界**：新增阅读 Controller、Service、DTO/Mapper 查询及测试；不抓取页面、不重做正文抽取、不读取原始 `HTML` asset、不实现 M6.1/M6.2 搜索分页。
- **为什么放这层**：所有权和路径解析由 Service 集中执行；Controller 只负责 HTTP 内容类型与响应头。

#### 5. 重难语法讲解

- **`Path.resolve(...).normalize()`**：将相对路径解析到根目录，再用 `resolved.startsWith(root)` 做路径段比较；不要用字符串 `startsWith`。
- **`InputStream.readNBytes(limit + 1)`**：多读一个字节以识别超限；只读 `limit` 会把“刚好截断”误当成完整 HTML。
- **`ResponseEntity<String>`**：显式设置 `text/html;charset=UTF-8` 与 `X-Content-Type-Options: nosniff`；不使用默认 JSON `ApiResponse` 包装，否则正文会被转义为 JSON 字符串。

#### 6. 具体实现

以下代码假设 `storage.root` 指向 M5.2 实际存储根目录，asset 表映射类为 `Asset`，字段映射遵循当前数据库设计文档。若已落地 M5.1 命名不同，只改 Mapper 和实体访问器，不改本阶段的授权、路径校验与响应契约。

##### `backend/src/main/java/com/webcollector/capture/asset/mapper/AssetMapper.java`

- **作用**：只查询目标用户拥有的链接及其最新清理正文资产。
- **完整代码**：

```java
package com.webcollector.capture.asset.mapper;

import com.baomidou.mybatisplus.core.mapper.BaseMapper;
import com.webcollector.capture.asset.entity.Asset;
import org.apache.ibatis.annotations.Mapper;
import org.apache.ibatis.annotations.Param;
import org.apache.ibatis.annotations.Select;

@Mapper
public interface AssetMapper extends BaseMapper<Asset> {

    @Select("""
            SELECT a.storage_path
            FROM asset a
            INNER JOIN link l ON l.id = a.link_id
            WHERE l.id = #{linkId}
              AND l.user_id = #{userId}
              AND a.asset_type = 'READABLE'
            ORDER BY a.created_at DESC, a.id DESC
            LIMIT 1
            """)
    String selectLatestReadablePath(
            @Param("linkId") Long linkId,
            @Param("userId") Long userId
    );
}
```

- **关键 3 行**：`l.user_id = #{userId}` 在数据库层隔离所有权；`asset_type = 'READABLE'` 不会误返回原始 HTML；`LIMIT 1` 保证结果为单条且最新。
- **怎么验证**：集成测试创建 Alice/Bob 两个用户及 asset；Alice 查自己的路径有值，查 Bob 的链接返回 `null`。

##### `backend/src/main/java/com/webcollector/capture/content/ReadableContentService.java`

- **作用**：校验链接归属、限制资产路径和读取大小。
- **完整代码**：

```java
package com.webcollector.capture.content;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.webcollector.auth.session.SessionTokenService;
import com.webcollector.common.web.BusinessException;
import com.webcollector.common.web.ErrorCode;
import com.webcollector.link.entity.Link;
import com.webcollector.link.mapper.LinkMapper;
import com.webcollector.capture.asset.mapper.AssetMapper;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.io.IOException;
import java.io.InputStream;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;

@Service
public class ReadableContentService {

    private static final int MAX_READABLE_BYTES = 2 * 1024 * 1024;

    private final LinkMapper linkMapper;
    private final AssetMapper assetMapper;
    private final SessionTokenService sessionTokenService;
    private final Path storageRoot;

    public ReadableContentService(
            LinkMapper linkMapper,
            AssetMapper assetMapper,
            SessionTokenService sessionTokenService,
            @Value("${storage.root:./data/archives}") String storageRoot
    ) {
        this.linkMapper = linkMapper;
        this.assetMapper = assetMapper;
        this.sessionTokenService = sessionTokenService;
        this.storageRoot = Path.of(storageRoot).toAbsolutePath().normalize();
    }

    @Transactional(readOnly = true)
    public String getReadableHtml(Long linkId) {
        Long userId = sessionTokenService.requireLoginId();
        Link ownedLink = linkMapper.selectOne(
                new LambdaQueryWrapper<Link>()
                        .select(Link::getId)
                        .eq(Link::getId, linkId)
                        .eq(Link::getUserId, userId)
        );
        if (ownedLink == null) {
            throw new BusinessException(ErrorCode.NOT_FOUND);
        }

        String storedPath = assetMapper.selectLatestReadablePath(linkId, userId);
        if (storedPath == null || storedPath.isBlank()) {
            throw new BusinessException(ErrorCode.NOT_FOUND);
        }

        Path relativePath = Path.of(storedPath);
        if (relativePath.isAbsolute()) {
            throw new BusinessException(ErrorCode.NOT_FOUND);
        }

        Path file = storageRoot.resolve(relativePath).normalize();
        if (!file.startsWith(storageRoot) || !Files.isRegularFile(file)) {
            throw new BusinessException(ErrorCode.NOT_FOUND);
        }

        try (InputStream input = Files.newInputStream(file)) {
            byte[] bytes = input.readNBytes(MAX_READABLE_BYTES + 1);
            if (bytes.length > MAX_READABLE_BYTES) {
                throw new BusinessException(ErrorCode.INVALID_REQUEST);
            }
            return new String(bytes, StandardCharsets.UTF_8);
        } catch (IOException exception) {
            throw new BusinessException(ErrorCode.NOT_FOUND);
        }
    }
}
```

- **关键 3 行**：`eq(Link::getUserId, userId)` 是链接级授权；`!file.startsWith(storageRoot)` 防止目录逃逸；`readNBytes(MAX_READABLE_BYTES + 1)` 可识别并拒绝超限文件。
- **怎么验证**：Service 单测覆盖不存在/他人链接、缺少正文、路径逃逸、缺失文件、超限文件和正常 UTF-8 HTML。

##### `backend/src/main/java/com/webcollector/capture/content/ReadableContentController.java`

- **作用**：将清理正文作为独立 HTML 响应返回。
- **完整代码**：

```java
package com.webcollector.capture.content;

import org.springframework.http.HttpHeaders;
import org.springframework.http.MediaType;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import java.nio.charset.StandardCharsets;

@RestController
@RequestMapping("/api/v1/links")
public class ReadableContentController {

    private final ReadableContentService readableContentService;

    public ReadableContentController(ReadableContentService readableContentService) {
        this.readableContentService = readableContentService;
    }

    @GetMapping("/{id}/readable")
    public ResponseEntity<String> getReadableContent(@PathVariable("id") Long linkId) {
        return ResponseEntity.ok()
                .contentType(new MediaType("text", "html", StandardCharsets.UTF_8))
                .header(HttpHeaders.X_CONTENT_TYPE_OPTIONS, "nosniff")
                .body(readableContentService.getReadableHtml(linkId));
    }
}
```

- **关键 3 行**：路由只暴露 link ID，不暴露磁盘路径；显式 UTF-8；`nosniff` 避免浏览器自行改变 MIME 判断。
- **怎么验证**：MockMvc 登录调用接口，成功断言 `Content-Type: text/html;charset=UTF-8`、`X-Content-Type-Options: nosniff` 和正文片段；匿名请求应由现有认证过滤器拒绝。

#### 8. 坑（会怎么错，不是要注意什么）

- ❌ 先按 `link_id` 查 asset，再在 Java 比较 owner → 会让授权漏在某条异常分支 → SQL 联查 `link.user_id` 并在 Service 再校验链接。
- ❌ 返回 `page.html` 或原始 `HTML` asset → 脚本可能在应用域执行 → 只允许 `READABLE` 类型。
- ❌ `Files.readString(file)` 无大小上限 → 大文件一次载入堆内存 → 流式读取并限制字节数。
- ❌ `file.toString().startsWith(root.toString())` → 相似目录前缀会被误放行 → 使用规范化 `Path.startsWith`。
- ❌ 直接用本机绝对路径写入数据库 → 部署目录变化后无法恢复且泄露布局 → 数据库仅存相对路径。

**能讲（先读参考回答，再凭记忆复述）**
- [ ] Q1：为什么不能只按 asset ID 查到文件后再检查链接 owner？查询层和 Service 层各自承担什么防线？
  - **参考回答**：ID 是客户端可猜测或获得的对象引用，不代表访问权限。查询 SQL 同时绑定 link ID 和 user ID，使数据库结果天然在用户范围内；Service 再验证拥有链接并统一把“不存在”和“非本人”映射成 `404`，避免泄露对象是否存在。两层不是重复替代，而是授权约束与业务边界校验。
- [ ] Q2：为什么正文 HTML 能返回，而抓取得到的原始 `page.html` 不能直接返回？`nosniff` 又解决什么？
  - **参考回答**：原始页面可能含第三方脚本、导航和表单；若在产品域名下直接执行，会把不可信网页内容带入应用安全上下文。本接口只返回抽取器生成的 `READABLE` HTML，并设置明确 MIME 和 `nosniff`，降低浏览器错误嗅探类型的风险；清理 HTML 仍需保持 M4.3 的脚本/噪音移除契约。
