# 2026-11-09 M9 本地自托管 MVP 最终复盘

> **一句话**：这篇复盘说明 WebCollector 如何从工程骨架走到真实网页保存、检索、运维和 `v0.1.0` 交付。🐋

## 目标与结果

第一版目标是把一个 URL 保存为可检索、可回看的资料快照。

最终范围包括：用户会话、集合、标签、链接、持久化抓取任务、HTML/PDF/截图、正文、搜索、Vue 工作台、管理员运营、本地部署、备份恢复、限流和真实 URL 验收。

不包含：公网部署、TLS、协作权限、公开分享、浏览器扩展、移动端和 AI 标签。

## 最重要的工程难点

- 链接、标签关联和 `PENDING` 任务必须同一事务创建，失败不能留下半条业务链路。
- 多 Worker 依靠 MySQL 行锁与 `FOR UPDATE SKIP LOCKED` 避免重复领取。
- 采集 URL 在首次请求和每次重定向后都要重新校验，阻断私网与云元数据地址。
- 成功终态与资产文件必须分别验证，数据库有记录但文件丢失不能算保存成功。
- ngram FULLTEXT 既要支持中文，也要强制按当前用户隔离。
- 前端不能把“接口成功”当成闭环，必须真实轮询任务、打开证据并能重新阅读。
- Compose 健康检查、可信代理头、Redis 故障关闭和备份哈希共同构成运行可信度。

## 证据边界

- M9.1 不是单个账号一次连续跑完 30 项；该混合证据方式由用户明确确认。
- 公网域名、TLS 和外部攻击面没有产品实测，不能写成已上线。
- Windows 符号链接限制导致 4 个安全测试跳过。
- 自动化通过不等于生产规模性能；真实指标只适用于当前固定数据集和环境。

## 学到的东西

- 先定义可观察的终态和失败边界，再写实现，比“接口返回 200”更能证明系统可用。
- 测试要验证用户拿到的结果，不能只验证 Mock 被调用。
- 运行证据必须带提交、环境、时间、输入和退出条件。
- 工程化不是多加组件，而是让每一步都能重复、定位和回滚。
- 单人自托管优先减少组件和攻击面；公网能力应作为独立阶段评估。
