# 二级阶段卡模板

> 用途：每个二级阶段开工前，Agent 必须先按本模板输出一张卡，再动手写代码。
> 放置：复制到项目根目录的 `docs/STAGE-TEMPLATE.md`，Agent 从 `AGENTS.md` §7 被指到这里。
> 原则：**宁可少写一节并注明"本步不涉及"，也不要为了填满栏目编内容。**

## 本项目适配（Web 收藏与内容保存系统）

本文件是模板的原文副本；项目差异只写在这一节，下面的模板正文一字不改。

- **编号**：模板里的 `{G}-{n}` 在本项目写成 `M<x>.<y>`，例如 `M2.6`；不再引入 G1–G6 这套一级阶段命名。
- **存放**：阶段卡落在 `docs/需求文档/YYYY-MM-DD-NNN-主题.md`，与 `007`、`009` 同级。
- **§6 实现**：只给类/方法签名、契约、关键伪代码或最小示例；后端生产代码由用户编写，测试代码由 Codex 编写。
- **§7 四大件**：没有真实机制就写“本步不涉及”，不硬凑。
- **§9 验收**：统一用 `mvn -pl backend test`；集成验证走真实 MySQL 8.4 / Redis 7.4 Testcontainers。
- **确认**：卡输出完等用户确认再写代码，用户说“直接做”才继续。

---

## 使用规则（给 Agent）

1. 十个节全部保留标题，内容没有就写"本步不涉及"，**不许删节、不许改序**。
2. §1 只列这一步真正用到的栈，不要抄整个项目的技术栈。
3. §2 只讲支撑 §4、§6 的原理；无关的放"延伸（选读）"或直接不提。
4. §6 只给这一步要改/新增的文件，不贴整个项目。
5. 卡输出完，等我确认再写代码。我若说"直接做"，按卡执行，不再解释。
6. 代码写完回来更新 §9 的勾选状态，未验证的写"未运行验证"。

## 精简版（小改动用）

改一个字段、加一个接口、修一个 bug 这类，用完整版会累。降到五节：

````markdown
### 二级阶段 {G}-{n}：{名称}
**一句话**：{做什么}　**完成标志**：{看到什么}

**改哪里**：{文件 + 函数/类 + 改什么}
**怎么改**：{步骤，含关键代码片段 + 为什么这么写}
**为什么这么做**：{一句话原理 + 不用会怎样}（不涉及写"无"）
**坑**：{1–3 条}
**验收**：{可执行判据} + {我要能讲清的 1 个问题}
````

**用哪个**：能改完不动脑筋的用精简版；需要先想清楚"放哪一层、为什么"的用完整版。

## 常见填错

| 症状 | 原因 | 修法 |
|---|---|---|
| §2 写成了教科书定义 | 没要求"不用会怎样" | 每讲一条原理必须配一个出事场景 |
| §7 硬凑四大件 | 模板没留出口 | 允许写"本步不涉及" |
| §6 贴了整个项目 | 没限定"只给改动文件" | 只贴这一步动过的 |
| §9 全是"能运行" | 验收写成了口号 | 每条要能执行、能观察 |
| 卡片写成文档，没人看 | 一次十节、每节一大段 | 全卡控制在 1.5 屏内，代码除外 |
