### 启动时序修复

首次启动时 backend 因 `Connection refused` 退出。根因是 MySQL 初始化阶段临时实例只监听 socket，而 Compose healthcheck 使用 `localhost` 时会被该临时实例提前判定为 healthy。健康检查改用 `127.0.0.1` 强制 TCP 后，重新创建 MySQL 容器并从头启动整套栈，backend 无需人工重启即可完成 V1–V17 迁移并启动。

## M8.2 执行记录

### 实现与测试

- `backup.ps1` 和 `restore.ps1` 显式接收 `ComposeFile`、`EnvFile`、`ProjectName`，所有 Compose 调用统一使用 `-p`、`--env-file`、`-f`。
- MySQL dump 先写入容器临时文件，再通过 `docker compose cp` 复制，避免 PowerShell 文本编码改写 SQL；备份结束后清理容器临时文件。
- 备份固定包含 `mysql.sql`、`assets/`、`capture-work/` 和带逐文件 SHA-256 的 `manifest.json`。
- 恢复前校验项目名、清单、文件大小、SHA-256 和未登记文件；恢复时先复制到容器暂存目录，再停止 backend、导入 SQL、替换两个目录并重启。
- 新增 `node --test .\deploy\tests\backup-restore.test.mjs`，6 项通过，覆盖二进制 SQL、双目录、清单完整性、拒绝覆盖、缺目录、哈希不一致、跨项目清单和停止写入顺序。
- 真实首次恢复发现容器暂存目录必须先创建；新增失败测试后修复为先执行 `mkdir -p`，再运行 `docker compose cp`。

## M8.3 执行记录

### 请求限流

- 登录、注册、创建链接分别按默认 `10/60s/IP`、`5/600s/IP`、`30/60s/用户 ID` 限流。
- Redis Lua 原子完成计数和 TTL；超限返回 429、`RATE_LIMITED`、`Retry-After` 和统一 `requestId`。
- Redis 不可用时失败关闭为 503；只有直连来源属于可信代理时才解析转发头，并优先采用可信 `X-Real-IP`。
