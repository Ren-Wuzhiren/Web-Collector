# M7 收口后完成 M8 Implementation Plan

**Goal:** 先完成 M7 的工程、动效与文档收口，通过用户学习门后再实施 M8 的部署、备份恢复、限流与验收。

**Architecture:** M7 修复 Vue 数字与页面过渡，并用 Playwright 固定动效和 reduced-motion 行为。M8 使用现有 Spring Boot/MySQL/Redis/Docker Compose 栈，在不新增数据库迁移的前提下加入 Redis 固定窗口限流、可运维日志、独立验收栈和可恢复备份。

**Tech Stack:** Java 17, Spring Boot 3.5.3, MyBatis-Plus, MySQL 8.4, Redis 7.4, Sa-Token, Vue 3, Vite, Playwright, Docker Compose, PowerShell.

**Spec:** `docs/需求文档/2026-10-07-007-架构设计各阶段任务清单.md`

## Global Constraints

- 严格执行 M7 收口门后进入 M8；M8 完成后才进入 M9。
- 不新增数据库表或 Flyway 迁移来实现限流。
- 后端生产代码默认由用户实现；Codex 提供接口/方法契约、测试、审查和文档。
- 未经明确要求不推送远端的任何 branch 或 tag。
- 当前工作区已有 M6/M7/M8 未提交改动，必须按里程碑隔离，禁止误提交无关文件。
- 正文不得使用 `v-html`；动效不得改变正文盒模型，reduced-motion 必须直接落到终态。
- 只有实际执行成功的测试、构建、浏览器检查和容器命令才能记为通过。
